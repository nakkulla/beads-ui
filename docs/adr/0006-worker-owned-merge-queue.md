# 세션은 PR 배달까지, 머지는 Worker 단일 큐가 소유

## Context

체인: 2026-05-13 `worker-board-redesign`이 Worker 보드를 세웠고, 2026-07-12
`worker-board-v2-ccx-queue`가 큐를 도입했으며, 2026-07-26
`worker-phase2-pr-queue`가 PR 단계를 큐에 넣었고, 2026-07-28
`pr-auto-merge-toggle`이 자동 등록 모드를 얹었다.

머지는 base에 쓰는 행위다. 두 머지가 동시에 시작하면 두 번째 PR은 첫 번째가 아직
쓰고 있는 base에 대해 BEHIND이거나 CONFLICTING이 된다. 세션이 각자 머지하면 그
동시성을 아무도 소유하지 않고, 게이트 재평가·충돌 해소 예산·대기 규칙이 세션
수만큼 복제된다. 또 세션은 자기 작업의 성공 여부를 자기가 판정하게 되어,
"머지했다"는 자기 보고가 완료 증거가 되는 구조가 된다.

## Decision

PR로 랜딩하는 작업에서 세션은 PR 배달까지만 한다. 워크스페이스의 모든 머지는
**하나의 순차 드라이버**가 실행한다 — `[머지]` 클릭은 더 이상 머지하지 않고 큐에
넣으며, 드라이버만이 실제 머지 호출의 단일 caller다. 자동 등록(`auto_merge`)이
켜져 있어도 드라이버를 우회하지 않고 같은 자격 판정과 같은 큐를 쓴다.

리뷰를 마친 `quick_fix`가 base ref를 직접 push하는 lane은 PR도 머지 호출도 아닌
별개의 계약 경로이며, 이 결정의 대상이 아니다.

완료는 세션의 보고가 아니라 **MERGED 관측**으로 판정한다. squash 명령이 0으로
끝났어도 PR이 merged로 관측되지 않으면 항목은 큐 머리를 유지하고 다시 관측된다.

세션이 직접 `gh pr merge`를 부르는 것은 실행 가드가 kill로 차단한다(ADR 0007).

## Considered Options

- **세션이 자기 PR을 직접 머지한다.** 동시성 소유자가 없어지고, 재게이트·충돌
  해소 예산·대기 규칙이 세션마다 중복 구현된다. 완료 판정이 자기 보고가 되는
  것도 함께 기각 사유다.
- **codex `/goal` → pr-finish 2단 파이프라인.** 머지 authority가 두 군데로
  갈라져 어느 쪽이 base를 쓰는지 관측 시점에 알 수 없다. 금지했다.

## Consequences

- 쉬워지는 것: 동시 머지로 인한 base 경합이 구조적으로 불가능하다. 재게이트,
  충돌 해소 라운드 상한, 대기 마감이 한 자리에만 있으면 된다.
- 어려워지는 것: 머지 처리량이 큐의 직렬 속도에 묶인다. 큐가 멈추면 모든 머지가
  멈추므로, 실패 항목은 종료가 아니라 건너뛰기로 처리해야 한다.
- 배제되는 것: 세션 자체 머지, 세션 보고 기반 완료 판정, 그리고 머지 authority를
  갖는 두 번째 파이프라인.
