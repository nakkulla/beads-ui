# 모니터 탭의 헤더 설정은 여러 저장소 일괄 적용 창이고 레포 카드 설정은 그 저장소만 편집한다

## Context

UI-8ncz는 여러 저장소에 실행 프리셋과 실행 계정·한도 정책을 적용하는 절을 모니터
덱 레포 카드의 `⚙` 패널에 두었다. 계정 절은 원본 저장소 하나의 값을 복사하는
방식이었다. 사용자의 의도는 달랐다. 레포 카드 `⚙`는 그 저장소만 설정해야 하고,
여러 저장소 적용은 모니터 탭에서 헤더 `⚙`를 눌렀을 때 떠야 한다.

헤더 `⚙`는 탭과 무관하게 설정 다이얼로그를 열고, 다이얼로그는 연결된 저장소에
묶여 있었다. 모니터 탭은 저장소를 고르지 않는 화면이라 연결 상태가 직전 저장소로
남는다. 그래서 모니터 탭의 헤더 `⚙`는 화면에 보이지 않는 저장소를 편집했다.

계정 카탈로그는 서버 기계 하나의 것이라 모든 저장소에서 같은 계정 키가 유효하다.
한도 자동 전환은 러너별 허용 계정 집합 안에서만 일어난다(ADR 0052).

## Decision

- 헤더 `⚙`의 창은 여는 순간의 탭으로 모드가 정해지고 닫힐 때까지 유지된다.
  모니터 탭에서 열면 일괄 모드, 다른 탭에서 열면 지금처럼 연결 저장소 하나의 창이다.
  다른 진입점(실행 프리셋 열기 등)은 단일 모드로 연다.
- 일괄 모드는 `워커`·`계정` 두 탭만 두고 실행 pane을 만들거나 읽지 않는다. 연결
  저장소를 편집하는 길은 이 모드에 없다. 모든 쓰기는 `적용 대상`에서 고른 저장소의
  `root_dir`을 지정한다. 초기 선택은 자동화가 켜진 행이다.
- `워커` 탭은 실행 프리셋 적용만 한다. 프리셋 관리는 단일 모드가 맡는다.
- `계정` 탭은 일괄 편집 폼이다. 모든 항목의 초기값은 `변경 안 함`이고, 바꾼 항목만
  선택한 저장소에 쓴다. 원본 저장소 값을 복사하지 않는다. 허용 계정을 바꾸면
  그 러너의 허용 집합 전체가 바뀐다.
- 서버 op는 새로 두지 않는다. 저장소마다 기존 단일 저장소 op를 순차로 보낸다.
  계정 쓰기가 실패한 저장소에는 정책 요청을 보내지 않는다. 결과는 저장소별
  적용됨·부분 적용·실패이고, 실패·부분 적용 저장소만 다시 적용할 수 있다.
- 레포 카드 `⚙` 패널은 그 저장소 하나의 편집만 가진다. 일괄 실행이 그 저장소에
  썼으면 열린 패널이 설정을 다시 읽는다.

## Consequences

- 같은 헤더 `⚙` 버튼이 탭에 따라 다른 창을 연다. 모니터 탭에서 숨은 연결 저장소를
  편집하는 결함이 사라진다.
- 레포 카드 패널에 일괄 절을 두는 방식, 모니터 전용 새 다이얼로그, 원본 저장소
  복사는 채택하지 않았다. 다이얼로그의 레일·포커스·닫기 처리를 한 벌로 유지하고,
  일괄 편집기와 단일 편집기의 상태가 섞이지 않게 하려는 것이다.
- 실행 pane의 계정 복사 원본 seam은 소비자가 없어 제거했다. 계정 카탈로그 읽기는
  실행 pane과 일괄 pane이 공유하는 모듈로 옮겼다.
- 자동화·동시 실행·직렬 레인·워크플로우 모드의 일괄 적용(ADR 0011)과 `비교`·`ADR`
  탭의 헤더 `⚙` 동작은 이 결정의 범위 밖이다.
