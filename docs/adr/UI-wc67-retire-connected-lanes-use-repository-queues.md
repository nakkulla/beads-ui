# 연결 레인을 폐기하고 저장소별 대기열에서 확인된 선행 대기만 건너뛴다

## Context

ADR 0041은 연결 레인의 진행 권한을 병렬·직렬 대기열에 적용하면서 사용자가 고른
위치를 보존했다. 그러나 의존 관계와 실행 위치를 연결 레인과 저장소별 대기열에서
함께 관리해야 했고, 직렬 선두가 외부 선행을 기다리면 뒤의 실행 가능한 작업도
멈췄다. 사용자는 연결 레인을 완전히 없애고 각 저장소의 대기열에서 다른 작업을
먼저 진행하도록 요청했다.

연결 레인 전용 화면·메시지·저장소·권한 소비자를 함께 제거해야 하므로 되돌리는
비용이 크다. 선행 대기만 직렬 순서의 예외로 인정하고 과거 의존을 보존하는 이유는
코드만으로 드러나지 않는다. 연결 레인의 별도 관리 기능과 엄격한 선두 장벽을
포기하는 대신 의존과 배치를 한 곳씩만 관리한다는 실제 절충이 있어 결정으로 남긴다.

## Decision

- 연결 레인은 폐기한다. 의존 관계는 일반 `blocks` 간선, 실행 위치는 저장소별
  병렬·직렬 대기열만 사용한다. 전용 프로토콜·저장소·투영·진행 권한과 조작을
  제거하며 저장소별 크로스레포 대기 영역이나 새 영구 실행 권한을 만들지 않는다.
- 대기 중 이슈는 레인·상대 순서·진입 시각을 보존한다. 비어 있는 직렬 레인은
  저장 순서로 살피되 실제 미해결 선행을 확인한 `prerequisite_unmet`만 건너뛴다.
  같은 저장소와 외부 저장소 선행에 같은 규칙을 적용한다. 닫힌 이슈는 기존 완료
  정리로 제외한다. 일시정지·처분 대기·유예·관측 실패와 그 밖의 거부는 뒤 항목을
  추월시키지 않는다.
- 직렬 실행은 한 번에 하나다. 실행 예약과 실행 중·PR 대기·정리 중 계보의 기존
  점유를 보존한다. 후보 선택과 명시적 시작, 예약과 실행 직전 확인은 같은 순서를
  판정하며 비동기 준비 중 레인·순서·앞 항목 준비 상태가 바뀌면 최신 상태로
  재판정한다. 오래된 admission만으로 추월하지 않는다.
- `[지금 시작]`은 지정한 이슈 하나의 실행 권한이다. 앞 항목들이 확인된 선행
  대기일 때만 같은 순서 예외를 적용하며, 지정 이슈가 막혀도 뒤 항목으로 권한을
  넘기지 않는다. 자동 진행과 자동 머지는 ADR 0011처럼 별개이고 기본값도 유지한다.
- ADR 0034의 외부 활동 이벤트·대기 재검사 경로를 계속 사용한다. 요청 저장소의
  `bd ready`가 확인한 이슈만 선행 대기를 지우고 원래 자리에서 보통 실행 후보로
  복귀한다. 이미 실행 중인 뒤 항목을 선점하지 않는다. 조회 실패나 순환 의존은
  해소됐다고 추측하지 않는다.
- 기존 `blocks` 간선·대기열·실행 세션·완료 이력은 보존한다. 과거 provenance를
  근거로 의존을 지우지 않는다. `cross-lanes.json`은 읽기·쓰기·자동 삭제·이관 없이
  퇴역 자료로 남기며 그 파일의 멤버를 자동 적재하지 않는다.
- 과거 큐와 attempt의 arm 필드는 실행·머지 권한으로 소비하지 않고 새 정규화와
  저장에서는 만들지 않는다. 과거 이력 파일은 다시 쓰지 않는다. 이미 머지 대기열에
  등록된 유효한 권한과 실행 중 세션은 취소하지 않는다.

## Consequences

외부 선행을 기다리는 작업의 배치를 유지하면서 같은 저장소의 다른 작업이 진행한다.
연결 레인별 관리 화면과 권한은 사라지고 기존 의존성 편집과 저장소별 대기열 조작으로
충분하다. 대신 직렬 순서 확인은 단순한 맨 앞 비교에서 확인된 선행 대기 예외와
비동기 상태 변화까지 판정해야 한다.

화면만 숨기는 대안은 전용 상태와 권한 소비자의 유지 비용이 남아 기각했다. 별도
외부 대기 영역은 순서와 대기를 중복 관리하므로 기각했다. 엄격한 선두 규칙 유지는
선행 대기 때문에 뒤 작업도 멈추는 사용자 문제를 해결하지 못한다.

폐기 후에도 저장소별 대기열과 선행 확인·직렬 점유 규칙은 계속 유효하므로 일회성
실행형 ADR이 아니다.
