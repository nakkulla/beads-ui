# 완료 행은 실행 사실과 워커 생성 출처를 함께 표시한다

## Context

Worker가 만든 이슈는 완료 뒤에도 생성 주체와 원본을 확인할 수 있어야 한다.
ADR 0037은 완료 행에 실행 사실을 표시하면서 출처 칩은 생략하도록 정했다.
이번 요청은 그 출처 금지 조항을 바꾼다. 실행한 주체와 생성한 주체가 다를 수
있으므로 실행 이력으로 생성 사실을 추정하지 않는다.

공유 생성 출처의 정의와 작성 규칙은 dotfiles 계약이 소유한다(ADR 0012).
이 결정은 그 값을 읽는 Worker·Monitor 공용 완료 카드의 표시만 정한다.

## Decision

- 완료 행의 슬롯 5는 route·오케/워커·`exec_receipt`·usage·작업 시간을 계속
  표시한다. 2줄 변형은 2번째 줄, 3줄 변형은 3번째 줄을 사용하며 줄을 늘리지
  않는다. 공용 렌더러와 슬롯 표는 ADR 0014를 따른다.
- 오케/워커는 완료를 만든 마지막 구현 attempt의 기록값에서 파생한다. 완료
  뒤 바뀔 수 있는 현재 실행 핀을 읽지 않고, 재료가 없으면 해당 칩만 생략한다.
  후보·대기용 실행 설정 칩의 배분에 완료 행을 넣지 않는 기존 규칙을 유지한다.
- 유효한 `worker_created_from`이 있으면 같은 슬롯 5의 경로 칩 다음에
  `워커 생성`과 `↩ 생성 원본 <ID>`를 표시한다. 생성 사실은 실행자나 완료
  상태가 바뀌어도 유지된다. 일반 `discovered-from` 관계만 있는 완료 이슈의
  출처 칩은 계속 생략한다.
- `워커 생성`은 클릭 동작 없는 사실 표시다. 생성 원본은 확인된 저장소로
  전환한 뒤 기존 상세 화면을 연다. 원본 저장소를 확인하지 못하면 ID와
  사유를 비활성 표시하고 현재 저장소의 다른 이슈로 이동하지 않는다.
- 부재·비정상 값에서 생성 사실을 추론하거나 보충하지 않는다. 생성 출처는
  실행 권한·대기열 배치·의존성 판정에 쓰지 않는다.

## Consequences

- 되돌리기 어려움이 성립한다. 공용 데이터 전달, 두 탭의 렌더러, 카드 슬롯
  문법과 사용자가 읽는 생성 출처를 함께 바꿔야 한다.
- 맥락 없이는 놀라움이 성립한다. 이전 결정이 출처 칩을 명시적으로 금지했기
  때문에 완료 행에 다시 표시하는 이유를 기록해야 한다.
- 실제 절충이 성립한다. 생성 사실을 이력에서 찾게 하는 대안 대신 완료 행의
  가로 공간을 사용한다. 기존 슬롯과 줄 수를 유지해 그 비용을 제한한다.
- 실행 사실과 생성 사실을 구분하면서 Worker와 Monitor가 같은 값을 같은
  문법으로 표시한다. 원본 조회 실패는 생성 사실 자체를 숨길 이유가 아니다.
