# 모니터 일괄 창은 워커·quick fix·세션·계정에 서버 전역 칩 바인딩을 편집하는 다섯 번째 탭 칩을 더하며 그 탭만 적용 대상 저장소와 무관하고 단일 창에는 없다 — 두 모드가 같은 네 탭이라는 점만 UI-uohc-2에서 뒤집고 나머지는 승계한다

## Context

ADR UI-uohc-2(2026-09-22)는 설정 다이얼로그의 실행 탭을 `워커`·`quick fix`·`세션`·`계정` 넷으로 정하고,
**단일 저장소 모드와 여러 저장소 일괄 모드가 같은 넷**을 쓴다고 했다. 그 창의 모든 탭은 `적용 대상`
저장소를 고르고 그 저장소의 현재 값을 읽어 세우는 "저장소 단위 편집면"이다.

ADR UI-wg68은 판정 칩 클릭이 적용할 프리셋을 **서버 전역** 바인딩 `chip_bindings`로 정했다(사용자
결정: 저장소별이 아니다). 그 값을 세울 표면이 필요한데, 서버 전역 값은 저장소 선택과 무관하므로 어느
저장소 창에 두어도 어긋난다. 탭 수의 변경은 UI-e1ta·UI-uohc-2가 함께 묶은 일괄 창의 탭 고정·관측
상태 기계·프리셋 관리 호출 지점을 같이 건드리므로, 한 조항의 반전을 전체 교체로 적고 UI-uohc-2를
superseded로 돌린다.

## Decision

모니터 탭 헤더 `⚙`의 일괄 창(`scope: 'monitor'`)에 다섯 번째 탭 `칩`(글리프 `⬡`)을 둔다.

- `칩` 탭은 `impl-presets-snapshot`의 `presets`·`chip_bindings`·`revision`만 읽고 쓴다. 행은
  `복잡`·`frontend`·`backend` 셋이고, 행마다 `<select>`가 `없음`과 현재 `general` 계열 프리셋 목록을
  담는다(비호환 프리셋은 `disabled`, quick_fix 계열은 없다). 고르는 즉시 `impl-preset-bind`를 보내고
  `conflict`면 스냅샷을 다시 받아 폼을 세운다. 저장 버튼은 없다. 스냅샷이 오기 전엔 행이 비활성이다.
- 이 탭만 `적용 대상` 저장소 선택과 무관하다. 전체 설정 창(`SETTINGS_TABS`)과 레포 카드 창
  (`REPO_SETTINGS_TABS`)에는 없다 — 저장소 하나를 편집하는 창에 서버 전역 값을 섞지 않는다. 따라서
  `REPO_SETTINGS_TABS`는 네 탭, `BULK_SETTINGS_TABS`는 그 넷에 `칩`을 더한 다섯이다.
- **승계.** UI-uohc-2에서 뒤집는 것은 "두 모드가 같은 네 탭" 조항 하나다. `quick fix` 탭의 계열별
  프리셋 바와 8행, 프리셋 선택이 그 탭 행만 `편집됨`으로 바꾸는 규칙, 관측 네 상태, 저장소별 순차 op와
  부분 실패 재적용, 모드 고정, 레포 카드가 헤더와 같은 다이얼로그로 열리는 것, 프리셋 관리는 그대로다.

## Consequences

네 탭은 저장소를 고르는데 다섯째 탭만 `적용 대상`과 무관한 이유는 창을 보면 드러나지 않으므로 탭
머리말 한 줄("서버 전역이라 적용 대상 저장소와 무관합니다")이 그것을 말한다.

대안으로 단일·레포 창의 `워커` 탭(프리셋 CRUD 자리) 안에 바인딩을 두는 안이 실재했고, 저장소 창에
서버 전역 값을 섞지 않으려고 버렸다. 탭은 지우기 쉬우나 바인딩을 세우는 유일한 표면이라 지우면
UI-wg68의 상태를 세울 곳이 없어진다.
