# 대기 사유에 따라 선행 자동 복귀와 보존 후보 이어하기를 구분한다

## Context

공통 종료 표식과 반복 기준 이동의 복구 한도는 dotfiles의
`docs/contracts/workflow-contract.md`가 소유한다. 이 저장소는 그 계약의 소비자다.
ADR 0028의 선행 대기는 작업을 시작하지 않은 결과이므로 선행 해소 뒤 새 attempt를
실행해도 된다. 반면 기준 브랜치가 다시 이동한 작업에는 이미 검증한 미인도 후보가
있다. 같은 자동 복귀를 적용하면 후보를 잃거나 구현을 중복 실행할 수 있다.

저장 상태·후보 보존·스케줄러·재개 소비자를 함께 바꿔야 되돌릴 수 있고, 같은
`waiting`의 서로 다른 출구는 사유 없이는 설명되지 않는다. 단일 자동 복귀의
단순함 대신 사유별 분기와 명시적인 이어하기를 선택한다.

## Decision

- `waiting`은 종료된 attempt의 기계 사실 대기이며 실패나 사람의 설계 결정 대기가
  아니다. 기존 `TERMINAL_ATTEMPT_STATUSES`와 정산 경로를 사용하고 실행 슬롯을
  해제한다. 새 Beads 상태·metadata·가짜 의존성은 만들지 않는다.
- `prerequisite_unmet`은 기존 선행 증명을 사용한다. 이 사유의 유일한 fence는
  `bd ready` 부재이며 선행 해소 뒤 보통 후보로 새 attempt를 실행한다. 기존 이벤트
  구독과 준비 상태 재검사, 선행 링크, 직렬 레인의 확인된 선행 대기만 추월하는
  규칙을 유지한다. 관측 오류나 모호한 결과는 대기로 추정하지 않는다.
- `base_moved`는 종료 표식의 후보와 기준 SHA를 검증한 경우만 인정한다. 현재
  attempt가 소유한 worktree·branch·head, 후보 부모와 기록 기준의 일치, 후보에
  결속된 검증·리뷰, 원격 이동과 미인도를 확인한다. 이미 인도한 후보는 기존
  실제 인도 증거로 정산한다. 코드 검증 실패나 소유권·원격 관측 불명은 대기로
  낮추지 않는다.
- 기준 이동 후보는 기존 `quickfix_landing`에 `cursor=null`,
  `head_sha=<candidate>`, `reason=base_moved`로 보존한다. 기준 SHA는 검증된 종료
  표식에서 복구한다. `target_base`는 브랜치 이름으로 유지하며 후보 SHA 자체를
  인도 증거로 삼지 않는다.
- 기준 이동 대기는 자동 새 구현을 막는다. `↻ 이어하기`만 기록된 세션·provider와
  같은 worktree·branch·후보를 검증해 최신 기준 반영부터 재개한다. 참조나 후보가
  없으면 그 사유로 거부하며 새 세션·worktree 생성이나 잔여물 회수로 대체하지
  않는다. 관계없는 Beads 이벤트로 fence를 지우지 않는다.
- 카드는 기존 슬롯 1 상태에 `반영 대기`, 같은 조작 슬롯에 공통 `.op-btn`인
  `↻ 이어하기`를 표시한다. 선행 대기의 링크와 자동 복귀는 유지하고 새 줄이나
  조작 종류를 만들지 않는다. 기계 정리 재시도는 별도 기존 출구를 유지한다.

## Consequences

선행 해소는 자동화하면서 미인도 후보는 같은 세션에서 보존한다. 대기 사유를
저장·투영·재개하는 모든 소비자가 함께 구분해야 하며, 기준 이동 대기는 명시적인
이어하기 전까지 남는다. 성공 문장만으로 완료를 선언하거나 필수 검증 실패를
대기로 숨기는 경로는 허용하지 않는다.
