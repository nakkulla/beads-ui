# 레인과 카드는 단일 buildLanes 계약과 공유 슬롯 표로 조립한다

## Context

Worker 탭과 Monitor 탭은 같은 사실(후보·실행 중·PR 대기·완료)을 각자 조립했다.
Monitor는 자기 카드 템플릿을, Worker는 자기 모델 빌더를 가졌고, 새
칩·뱃지·버튼은 카드마다 자기 자리를 골랐다. 그 결과 같은 사실이 탭에 따라 다른
모양으로 그려졌고, 칩이 하나 끼면 조작 버튼이 다음 줄로 밀려 사용자가 버튼을
찾는 자리가 화면 폭에 따라 달라졌다.

세 설계가 차례로 이를 합쳤다: 2026-08-25 카드 헤더 문법 통일이 슬롯 표를 만들고,
2026-08-27 레인 표면 통일이 두 탭의 렌더러를 합치고, 2026-08-27 레인 모델 통일이
마지막 남은 조립 분기를 없앴다.

## Decision

레인 조립은 순수 함수 `buildLanes(workspaces, workspaces_state, options)`
하나다. 입력 단위는 언제나 워크스페이스 항목 N개이며, Worker 탭은 자기 store의
열들을 어댑터로 그 모양 하나로 접어 넣는다. Worker 전용 모델 빌더는 존재하지
않는다.

카드 렌더러는 두 탭이 공유한다. 줄 순서와 새 요소가 놓일 자리는 카드가 고르지
않고, 그 요소가 답하는 질문으로 카드 헤더 문법 스펙의 슬롯 표가 정한다. 재료가
없는 줄은 그리지 않고, 조작은 첫 줄 오른쪽 끝이거나 액션 foot이며 그 사이에 칩을
끼우지 않는다. 슬롯 표에 없는 요소가 필요하면 칩을 추가하기 전에 스펙을 먼저
갱신한다.

## Considered Options

- **탭별 개별 조립 유지** — 기각. 같은 사실을 두 모양으로 그리는 것이 통일 전
  상태를 만든 원인이고, 조립 분기가 남아 있는 한 새 칩은 다시 두 번 배치된다. 두
  탭의 차이는 실제로는 Monitor에만 있는 두 번째 축(레포)뿐이며, 그 축은 조립기를
  나누지 않고도 표현할 수 있다.
- **카드별 자율 배치 유지** — 기각. 자율 배치는 카드 하나를 고칠 때는 싸지만,
  조작 위치의 예측 가능성을 화면 폭에 넘긴다.

## Consequences

- 쉬워지는 것: 새 칩은 슬롯 표에서 자리를 받아 한 번만 구현하면 두 탭에 같은
  모양으로 나타난다. 레인 판정의 회귀 테스트도 한 곳이다.
- 어려워지는 것: 한 탭에만 필요한 표시도 공용 계약을 통과해야 한다. 슬롯이 없는
  요소는 스펙 갱신이 선행되므로 즉흥적인 추가가 느려진다.
- 배제되는 것: 탭 로컬 카드 템플릿, 탭 로컬 레인 모델, 그리고 단일
  워크스페이스를 전제하는 조립 경로.
