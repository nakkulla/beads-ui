# 모니터 탭의 설정은 저장소의 현재 값을 읽어 세우고 갈리거나 읽지 못한 행은 적용에서 빠지며 일괄 창은 세 탭과 프리셋 관리를 갖고 레포 카드 설정은 같은 다이얼로그로 열린다 — 모드 고정·순차 op·결과 형식·계정 명시 선택은 UI-628r을 승계한다

## Context

ADR UI-628r(2026-09-21)은 모니터 탭 헤더 `⚙`의 여러 저장소 창을 24키 실행 프로필
편집면으로 넓히면서 "이 창은 저장소들의 현재 설정을 보여주는 화면이 아니다"를 함께
정했다. 갈린 행의 초기값을 무엇으로 둘지 답이 없다는 것이 그 이유였다. 같은 ADR은
일괄 모드를 `워커`·`계정` 두 탭으로 고정하고 프리셋 관리를 단일 창에만 두었으며,
레포 카드 `⚙`는 덱 안 인라인 패널로 남겼다.

실제로 써 보니 창을 열 때마다 24행이 전부 `기본값 사용`에서 시작해 방금 일괄
적용한 값조차 화면에 남지 않았다. 레포 카드 `⚙`는 덱 안에서 아래로 펼쳐지고 헤더
`⚙`는 다이얼로그라 같은 성격의 조작이 두 형태로 열렸다. 사용자는 2026-09-21에 세
지점 — 적용된 값이 보이게, 세션 탭도, 레포 카드 설정도 팝업으로 — 을 함께 지목했고,
갈린 행에 대해서는 "채우지 말고 갈려 있다고만 표시되어도 된다"고 답을 냈다.

재료는 대부분 화면에 있었다. 모니터 행은 세션 기본값 21키와 `provider_limit_policy`,
큐의 오케스트레이션 6키를 싣고, `createExecutionPane`은 `root_dir` 바인딩으로 다른
저장소를 편집한다. 없던 것은 저장소별 실행 계정과 큐의 `applied_exec_preset` 기록,
그리고 서버가 차가운 캐시·만료·읽기 실패를 모두 빈 레이어로 싣어 화면에서 `조회
전`과 `확인된 부재`가 같은 모양으로 도착한다는 사실이었다.

## Decision

이 ADR은 UI-628r을 대체한다. 아래 첫 네 항목은 UI-628r에서 그대로 살아남은 결정이고,
그 뒤 항목들이 이번에 바뀐 것이다.

- 헤더 `⚙`의 창은 여는 순간의 탭으로 모드가 정해지고 닫힐 때까지 유지된다.
  모니터 탭에서 열면 일괄 모드, 다른 탭에서 열면 연결 저장소 하나의 창이다. 모든
  일괄 쓰기는 `적용 대상`에서 고른 저장소의 `root_dir`을 지정하며 초기 선택은
  자동화가 켜진 행이다.
- 서버 op는 새로 두지 않는다. 저장소마다 기존 단일 저장소 op를 순차로 보낸다.
  결과는 저장소별 적용됨·부분 적용·실패이고, 실패·부분 적용 저장소만 다시 적용할
  수 있다. 계정 쓰기가 실패한 저장소에는 그 저장소의 정책 요청을 보내지 않는다.
- `기본값 사용`은 `변경 안 함`이 아니라 "이 저장소에 값을 두지 않는다"는 실제
  설정이며 적용하면 그 키가 지워진다. 화면에 값이 선 행은 손대지 않아도 그대로
  쓰인다. 프리셋 기록(`applied_exec_preset`)을 세우고 푸는 판정은 서버가 소유한다.
- `계정` 탭에 `변경 안 함`은 없다. 허용 계정을 바꾸면 그 러너의 허용 집합 전체가
  바뀌고, 두 러너 가운데 하나라도 계정 카탈로그를 읽지 못하면 계획이 비고 `[적용]`이
  잠긴다.
- **일괄 창은 선택한 저장소의 현재 값을 읽어 세우는 관측면이자 편집면이다.** 행마다
  관측은 넷이다 — `같음`(그 값이 선다), `비어 있음`(`기본값 사용`이 선다),
  `갈림`(서로 다른 값이 둘 이상; 값이 서지 않는다), `미확인`(고른 저장소 가운데
  하나라도 그 층을 아직 읽지 못함; 값이 서지 않는다). `갈림`과 `미확인` 행은
  사용자가 손대기 전까지 적용 payload에서 빠져 저장소별 현재 값을 유지하고,
  `[적용]`은 그 행 때문에 잠기지 않는다. 사용자가 고친 행은 `편집됨`이며 이후
  관측 갱신이 덮지 않는다. 프리셋을 고르면 25행 전부가 `편집됨`이 된다.
- **`미확인`은 `비어 있음`과 갈라진다.** 층은 둘이고 읽힘 판정이 다르다: 세션
  기본값 층은 행의 `session_defaults_state`가 `ready`일 때, 워크스페이스 계정 층은
  `workspace_accounts`가 실려 있고 `state`가 `unusable`이 아닐 때 읽힌 것이다. 큐에서
  오는 값에는 조회 상태가 없다. 조회 실패로 캐시된 층도 `pending`으로 투영한다 —
  값을 읽지 못한 것은 값이 없다는 뜻이 아니다. `session_defaults_state`를 주지 않는
  구버전 서버에서는 `미확인`을 만들어 내지 않고 값 그대로 관측한다.
- **서버 모니터 행은 세 필드를 더 싣는다.** `workspace_accounts`(계정 층,
  `session_defaults`와 같은 prewarm 캐시 경로; 아직 읽지 못한 행은 필드 자체가 없다),
  `session_defaults_state`(`ready`|`pending`), `applied_exec_preset`(큐 기록 그대로,
  없으면 `null`). 새 op도, 요청 payload 변경도 없다. `set-workspace-accounts`
  성공은 그 저장소의 계정 층 캐시를 무효화해 다시 푸시한다.
- **일괄 창은 `워커`·`세션`·`계정` 세 탭이고 프리셋 관리도 갖는다.** `워커` 탭은
  25행 — 24키에 `impl_dispatch` 한 행을 더한 것 — 이며 `impl_dispatch`는 프리셋에만
  담기고 저장소에는 쓰지 않는다(ADR 0012). 프리셋 바는 단일 창과 같은 세 op를 그대로
  부르고, 값이 서지 않은 행이 하나라도 있으면 저장 버튼만 잠긴다. 폼이 고른 프리셋과
  값이 같을 때만 `apply-impl-preset-global`을 쓰되, 보류 행이 하나라도 있으면 같다고
  보지 않는다. 읽기 전용 `적용된 프리셋` 줄은 기록의 `id` 하나로 비교하고 이름은
  현재 프리셋 목록에서 `id`로 찾는다(ADR UI-xq3h). `세션` 탭은 `workflow_mode`·
  `bdui_url`·`base_sync_accept_local_commits` 세 행을 저장소 defaults만 읽고 쓴다(ADR
  UI-wecw). 계정 선택지는 두 창 모두 `accountRowLabel` 한 포맷터로 사용량 창을 붙인다.
- **레포 카드 `⚙`는 헤더 `⚙`와 같은 다이얼로그를 그 저장소 단일 모드로 연다.**
  `{ scope: 'repo', root_dir }`로 열려 `워커`·`세션`·`계정` 세 탭과 `root_dir`에 바인딩한
  `createExecutionPane` 하나를 그린다. 덱 안 인라인 패널과 일괄 적용 뒤 열린 패널을
  다시 읽던 `reloadPanel` 배선은 없어진다 — 두 창이 동시에 열리지 않으므로 재읽기
  계약은 "일괄 적용 뒤 레포 창을 열면 새 값을 읽는다"로 대체된다. 열려 있는 동안
  그 저장소 행이 목록에서 사라지면 창을 닫는다.

## Consequences

- 창을 열면 저장소들이 지금 무슨 값으로 도는지 그 자리에서 읽고 바꿀 행만 고친다.
  `갈림`은 관측된 사실이라 사용자가 고를 수 없고 값이 갈린 행에만 선다 — `변경 안 함`의
  부활이 아니다.
- 아직 보지 못한 설정을 지우는 요청은 만들어지지 않는다. 투영에 조회 상태 한 필드를
  더한 비용으로 그 경로를 닫았다.
- 기각한 대안은 다섯이다. (1) 갈린 행을 대표값으로 채우기 — 읽는 사람이 보지 못한
  값이 서고 소수 저장소를 덮는다. (2) 읽기 전용 요약만 덧붙이기 — 보고 고치는 화면이
  되지 못한다. (3) 조회 상태 없이 빈 레이어를 부재로 읽기 — 읽지 못한 설정의 삭제
  요청이 된다. (4) 인라인 패널을 모달 오버레이로만 감싸기 — 두 진입점의 형태가 여전히
  갈린다. (5) UI-628r 유지.
- 되돌림 비용이 있다. 관측 모듈(`bulk-observation.js`), 편집 상태 기계, 세션 탭 적용
  경로, 서버의 세 투영 필드와 조회 상태 계약, 프리셋 관리의 두 번째 호출 지점, 덱
  패널 제거와 다이얼로그의 저장소 바인딩 모드가 모두 이 결정에 묶인다.
- 이 창은 카드가 아니므로 ADR 0014의 슬롯 표 대상이 아니다. 시스템 프롬프트,
  자동화·동시 실행 수·직렬 레인의 일괄 적용, 이슈 상세 패널의 계정 줄은 범위 밖이다.
