# auto_merge와 auto_advance는 별개의 스위치

## Context

워크스페이스의 자동화에는 성격이 다른 두 가지가 있다. `auto_advance`는 준비된
Bead에 실행 세션을 붙이고, `auto_merge`는 자격을 얻은 PR을 머지 큐에 계속
등록한다. `[일괄 머지]`가 클릭 순간의 스냅샷만 처리하는 일회성 액션이던 것을
2026-07-28 설계가 durable 토글로 바꾸면서, 두 자동화를 "자동화" 스위치 하나로
합치자는 단순화가 실제로 검토됐다. 사용자 입장에서 둘 다 "알아서 굴러가게 하는
것"으로 보였기 때문이다.

## Decision

두 값은 워크스페이스 큐에 독립된 필드로 저장되고, 툴바의 독립된 버튼(`▶ 자동화`
/ `▶ 자동 머지`)으로 각각 조작한다. 한쪽이 켜져 있어야 다른 쪽이 동작하는 관계는
없다. 머지 큐 항목의 authority는 또 다른 축(사용자가 직접 등록한 항목의
continuation)이며, 전역 `auto_merge` 토글이 그 authority를 소유한 적은 없다.

## Considered Options

- **단일 "자동화" 스위치** — 기각. 되돌릴 수 있는 것과 되돌릴 수 없는 것을 같은
  클릭에 묶는다. 자동 진행된 세션은 멈추고 결과를 버리면 되지만, base에 랜딩된
  머지는 되돌릴 수 없다. 세션을 굴리려고 켠 사용자가 머지 권한까지 함께 주게
  된다.
- **한쪽을 다른 쪽의 전제로 두기**(자동 머지는 자동 진행이 켜져 있을 때만) —
  기각. 세션은 사람이 직접 붙이고 머지만 자동으로 흘리고 싶은 사용이 실제 사용
  패턴이었다.

## Consequences

- 쉬워지는 것: 자동화 수준을 축별로 고를 수 있다. 머지를 멈추는 데 실행을 멈출
  필요가 없고, 그 반대도 같다.
- 어려워지는 것: "왜 안 도는가"의 답이 두 군데에 있다. 화면과 `/healthz`가 두
  값을 모두 노출해야 한다.
- 배제되는 것: 하나의 마스터 자동화 스위치, 그리고 전역 토글이 항목별
  authority를 대신 소유하는 설계.
