# 준비된 nosync 경로를 작업 폴더 생성 전에 반영

Bead: UI-o4in
상태: 사용자 승인 전 초안

## 1. 문제와 근거

Cortex-1wa의 2026-09-10 실행은 실제 `.worktrees/Cortex-1wa` 안에서 시작했다.
승인 스펙 `2026-09-10-thalamus-absorption-design.md` §5.6은 워크트리 생성
전에 `.worktrees → .worktrees.nosync`를 만들도록 요구한다. 세션이 이 조건을
검사할 때는 자기 작업 폴더가 이미 들어 있어 빈 디렉터리 조건이 깨져 있었다.
조사 시 Cortex의 `.worktrees.nosync` 실디렉터리는 존재했다.

`server/worker/worktree.js`의 `add`, `restore`, `addDetached`는 `.worktrees`
하위 경로로 바로 `git worktree add`를 실행한다. 이미 준비된 링크는 사용할 수
있지만 링크를 준비하지는 않는다. `deploy-lock.js`도 잠금 파일을 열기 전에
부모 디렉터리를 직접 생성한다. 따라서 구현 세션 안의 확인이나 `add` 한 곳의
수정만으로는 최초 생성 순서를 보장할 수 없다.

공통 dotfiles 계약은 논리 경로 `.worktrees/<Bead ID>`를 정한다. 별도의
nosync 선택 키는 없고 `repo-ops/config.toml`은 경로 설정을 소유하지 않는다.
이번 설계는 그 논리 경로를 유지한다.

## 2. 목표와 선택

동기화에서 제외할 폴더를 이미 준비한 저장소에서 Worker가 새 실디렉터리를
잘못 만들지 않도록, 최초 쓰기 전에 링크 준비를 수행한다.

- 채택: 기존의 정상 `.worktrees` 링크가 우선한다. 링크가 없고
  `.worktrees.nosync` 실디렉터리가 있으면 이를 저장소의 선택으로 해석한다.
  별도 설정 파일 없이 현재 Cortex의 준비 상태를 사용할 수 있다.
- 대안: 저장소마다 수동으로 링크만 만들어 둔다. 당장 우회는 가능하지만
  준비된 nosync 폴더를 무시하고 실디렉터리를 만드는 실행 경로가 남는다.
- 대안: 공통 계약에 경로 설정 키를 새로 추가한다. 명시적이지만 계약 생산자와
  소비자에 새 설정을 도입해야 하므로 이번 문제에 필요한 범위를 넘는다.

`.worktrees.nosync`라는 이름만으로 iCloud 자체의 제외 동작을 검증했다고
주장하지 않는다. 이번 검증 대상은 Git 작업 폴더의 실제 저장 위치다.

## 3. 상태별 처리

새 모듈 `worktree-container.js`가 동기 파일시스템 함수
`prepareWorktreeContainer(repo, fs)`를 제공한다. 반환값은 검증된 컨테이너의
논리 경로와 실제 경로다. 호출 때마다 관측하며 상태 캐시를 두지 않는다.

| 관측 상태 | 처리 |
| --- | --- |
| `.worktrees`가 정상 디렉터리로 해석되는 링크 | 기존 대상을 그대로 사용한다. 상대·절대 링크 모두 허용한다. |
| `.worktrees`가 끊어진 링크·일반 파일·순환 링크 | 덮어쓰거나 일반 디렉터리로 대체하지 않고 경로를 포함한 오류를 반환한다. |
| `.worktrees`가 없거나 실디렉터리이며 nosync 항목도 없음 | 기존 `.worktrees` 디렉터리 사용 방식을 유지한다. 없으면 생성한다. |
| 정상 링크가 없고 nosync 항목이 실디렉터리가 아님 | 잘못된 준비 상태로 거부한다. 일반 경로로 조용히 우회하지 않는다. |
| nosync 실디렉터리 존재, `.worktrees` 없음 | 상대 링크 `.worktrees → .worktrees.nosync`를 생성한다. |
| nosync 실디렉터리 존재, `.worktrees`가 빈 실디렉터리 | `rmdir`로 빈 디렉터리만 제거한 뒤 상대 링크를 생성한다. |
| nosync 실디렉터리 존재, `.worktrees`가 비어 있지 않은 실디렉터리 | 어떤 항목도 옮기거나 지우지 않고, 별도 전환이 필요하다는 경로 포함 오류를 반환한다. |

nosync 선택을 적용한 뒤에는 `realpath(.worktrees)`와
`realpath(.worktrees.nosync)`의 일치를 확인한다. 폴더가 실제로 존재하며
디렉터리인지도 확인한다. 링크 생성 실패를 무시하고 후속 쓰기를 하지 않는다.

동시에 같은 링크를 만드는 다른 프로세스 때문에 생성이 실패한 경우에만
한 번 다시 관측하여 동일한 정상 링크가 완성됐으면 성공으로 취급한다.
다른 대상·비어 있지 않은 디렉터리·읽기 실패는 그대로 거부한다. 재귀 삭제,
강제 링크 교체, 디렉터리 rename, 일반 경로 폴백은 사용하지 않는다.
빈 디렉터리를 제거한 뒤 링크 생성에 실패하면 링크가 없는 상태를 보고하며,
다음 실행은 같은 준비 함수로 다시 판단한다. 별도 복구 상태를 저장하지 않는다.

## 4. 호출 순서와 소비자

- `add`와 `restore`: 기존 Git 작업 직렬화 잠금 안에서, 브랜치 생성이나
  워크트리 추가 전에 준비한다. `restore`의 기존 거부 결과 형태를 유지한다.
- `addDetached`: 기존 잠금 안에서 잔여 워크트리 정리보다 먼저 준비한다.
  준비에 실패하면 기존 경로에 대한 강제 정리도 실행하지 않는다.
- `acquireDeployLock`: 부모 디렉터리를 직접 만드는 코드를 준비 함수 호출로
  대체한다. 링크 검증 뒤 잠금 파일을 열어 기존 파일 잠금 계약을 유지한다.
- 배포 워크트리 `ensureAligned`: 신규 생성 전에 같은 준비를 수행한다.
  정상 링크 뒤의 Git 등록 경로는 실제 경로로 비교하여 자기 배포 워크트리를
  외부 작업으로 오판하지 않는다. 기존 detached·공통 Git 저장소 확인은 유지한다.
- `pathFor`, attempt 기록, 서비스 경로, 잠금 파일 이름은 계속 논리 경로
  `.worktrees/...`를 사용한다. 기존 제거·관측의 실제 경로 비교를 재사용한다.
- 실패는 각 호출자의 기존 오류 전파 방식으로 전달한다. 새 실패 계층,
  자동 재시도 횟수, 대기 상태나 UI 조작은 추가하지 않는다.

결정: 공통 workflow metadata와 repo-ops 설정 스키마는 바꾸지 않는다 —
이 변경은 beads-ui의 파일시스템 준비 동작이며 계약 경로 자체는 유지한다.

## 5. 이미 실패한 Cortex 실행의 처리

자동 준비 함수는 현재 비어 있지 않은 Cortex 컨테이너를 자동 이관하지 않는다.
공통 수정 후 이번 세션이 기존 실행의 PID·작업 폴더·브랜치·HEAD·작업 상태와
Git 등록을 다시 읽고, `.worktrees` 및 `.worktrees.nosync`의 모든 항목을 확인한다.

중지된 이슈 전용 워크트리이고 목적지 충돌이 없음을 확인하면 Git의
`worktree move`로 해당 폴더를 `.worktrees.nosync/Cortex-1wa`로 옮기는
구체적 전환을 준비한다. Git 지원 조건을 확인하고 강제 옵션은 사용하지 않는다.
이동 전후 HEAD·변경 내역·Git 등록을 비교하며 다른 작업은 처리하지 않는다.
기존 컨테이너가 빈 것이 확인된 뒤에만 링크 준비를 수행한다.
활성 실행·등록 불일치·대상 충돌이면 관측된 원인과 필요한 판단을 제시한다.

이 운영 전환은 Cortex의 추적 파일·승인 키·원격 커밋을 바꾸지 않는다.
스펙 §5.6의 메인 전환 변경 정리는 별개이며, 본 수정의 완료를 이유로
Cortex-1wa 구현을 자동 재시작하지 않는다. 경로 문제 해결과 원래 작업의
전체 선행 조건 충족을 구분해 보고한다.

## 6. Test scope

새 의존성 없이 임시 Git 저장소와 기존 Vitest 도구를 사용한다.

- 준비 함수: 상태 표 각 분기, 반복 호출, 정상 외부 링크 보존,
  끊어진 링크·일반 파일·비어 있지 않은 디렉터리의 내용 보존,
  생성 경쟁 후 같은 대상만 수용, 링크 생성 실패 뒤 후속 쓰기 금지.
- 실제 Git 통합: nosync만 있는 저장소 및 빈 `.worktrees`가 있는 저장소에서
  첫 `add`의 실제 작업 위치와 `git worktree list`가 nosync 아래인지 확인.
  제거 후 재생성도 같은 위치를 사용하고 일반 저장소는 기존 동작을 유지한다.
- `restore`와 `addDetached`도 준비된 nosync를 사용하며, 비어 있지 않은
  잘못된 컨테이너 거부 시 기존 파일과 Git 등록이 보존되는지 확인한다.
- 배포 잠금: 첫 잠금 파일의 실제 위치가 nosync 아래이며 두 획득자가 같은
  잠금을 공유하는지 확인한다. 잘못된 컨테이너에서는 잠금 프로세스를 띄우지 않는다.
- 배포 워크트리: 링크 뒤의 detached 워크트리를 생성·재사용·정렬할 수 있고
  외부 또는 다른 저장소의 등록은 계속 거부하는지 확인한다.
- 검증 명령: 해당 통합 테스트 → `npm run tsc` → `npm run lint` →
  `npx prettier --write <변경 파일>` → `npx vitest run --reporter=dot`.
  저장소 지침에 따라 새 구현 워크트리의 Node 버전과 자체 의존성 설치를 확인한다.
- 배포 검증: PR 머지 뒤 Worker의 배포 증거를 확인한다. Cortex 운영 전환은
  위 §5의 실제 경로·Git 등록·HEAD·변경 보존으로 검증한다.

## 7. 경계·후속

하나의 beads-ui 구현 단위다. Cortex 운영 전환은 기존 Cortex-1wa 상태를
보존하는 로컬 경로 복구이며 별도 코드 변경을 포함하지 않는다.
메인 전환 변경의 커밋·동기화는 기존 Cortex-1wa 스펙의 승인 경계가 소유한다.
새 형제 Bead나 공통 설정 계약 변경은 필요하지 않다.

## 결정 (ADR 후보)

- 전제: ADR 0010 — 배포의 실행과 잠금은 Worker가 소유하고 저장소별 배포
  명령은 기존 선언을 유지한다.
- 정상 링크 우선, 링크가 없을 때 준비된 nosync 실디렉터리를 사용한다 —
  되돌리기 어려움: 불성립. 준비 로직을 제거해도 기존 파일과 링크는 보존되고
  생성 전 수동 준비로 돌아갈 수 있다. 맥락 없이 의외임: 성립. 디렉터리 존재를
  저장 위치 선택으로 해석하는 이유는 동기화 제외라는 맥락이 있어야 이해된다.
  실질적 대안·절충: 성립. 수동 준비 및 새 설정 키와 비교해 기존 디렉터리의
  의미를 확장하는 대신 설정 계약 추가를 피한다. 세 조건을 모두 충족하지
  않으므로 이 스펙에 근거를 남긴다. → ADR 아님
