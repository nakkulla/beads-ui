# 한도 대응에 러너별 전역 적용 스위치를 두고 전역 로그인 자동 전환을 그 설정에 묶는다 (UI-giog)

## 1. 배경

2026-11-09 Worker `ops` 알림 `🔁 Claude 활성 계정 자동 전환 — 계정 #3 → 계정 #4`를 본 사용자가, 설정의 저장소별
`한도 대응: 기다림 / 자동 전환`과 같은 말이라 헷갈린다고 지적했다. 두 동작은 층이 다르다. 저장소 정책은 그 저장소
Worker가 다음 실행에 쓸 계정(`cswap run <계정>`)을 정한다. 알림의 전환은 Mac 전체 로그인(`cswap switch`)을 바꿔
대화형 세션·Hermes·계정 없는 Worker attempt 모두에 영향을 준다. 그런데 이 전역 전환은 자기 설정이 없다. 저장소
정책을 빌려 판정한다(활성과 후보를 함께 허용한 switch 저장소가 있어야 하고, 기본 계정 없는 wait 저장소가 있으면
보류한다).

사용자 결정(2026-11-09, 이 세션):
- 전역 교체가 저장소별 설정을 따르는 것은 맞지 않다 — 저장소마다 기다림/자동 전환이 다를 수 있다.
- 전역 적용 스위치로 "전역 설정을 적용할지, 저장소별 설정을 유지할지"를 고른다. 켜면 전역 자동 전환/기다림이
  적용되고, 끄면 저장소별 설정이 적용된다.
- 끄면 전역 로그인은 자동으로 바꾸지 않는다.
- 스위치는 러너(Claude·Codex)별로 따로 둔다.
- 전역 설정 블록은 모니터 ⚙ `전역` 탭에만 둔다.

## 3. 목표와 비목표

목표:
- 러너마다 서버 전역 한도 정책(`대응 방식`·`전환 허용 계정`·`선제 전환`)과 `적용 범위: 저장소별 / 전역` 스위치를 둔다.
- `전역`이면 모든 등록 저장소의 그 러너 Worker 판정과 전역 로그인 자동 전환이 전역 정책 하나를 따른다.
- `저장소별`이면 Worker는 각 저장소 정책을 따르고, 전역 로그인은 자동으로 바뀌지 않는다.
- 알림과 화면이 "전역 로그인"과 "저장소별"을 같은 말로 섞지 않는다.

비목표:
- 저장소 정책의 저장 형식·쓰기 경로 변경. 저장된 값은 그대로 남는다.
- 보류 카드 문구(`계정 전환 안 함 · 기다림 모드` 등)의 변경과 새 카드 슬롯.
- Worker 후보 기준(80/90), 크레딧 설정, 기다림 추종(UI-np4t) 규칙 자체의 변경.
- 저장소 기본 계정(`workspace_exec_accounts`)의 의미 변경.

## 4. 설계

### 4.1 정한 갈림

- 결정 — **적용 범위 스위치**: 러너별 `scope: 'repo' | 'global'`이다. `global`이면 그 러너의 실효 정책은 전역 정책이고, `repo`면 저장소 정책이다 (대안: 켤 때 전역 값을 각 저장소에 복사; 이유: 끌 때 원래 저장소 설정으로 돌아갈 수 없다).
- 결정 — **덧씌우기**: 저장소 정책은 읽기 시점에 실효 정책으로 바뀌고 저장 값은 건드리지 않는다. §4.3의 소비자는 모두 한 실효 정책 함수를 거친다 — 파일마다 `scope`를 다시 판정하지 않는다.
- 결정 — **전역 정책 모양**: 저장소 정책과 같은 `{ mode, accounts, preempt_pct }`이고 검증 규칙(계정 키, 1~99 정수 또는 `null`)도 같다. 빈 허용 목록의 `switch`는 저장소와 같이 `unconfigured`다.
- 결정 — **초기값**: 파일이 없거나 깨졌으면 두 러너 모두 `scope: 'repo'`, 전역 정책은 저장소 기본값(`switch`·빈 목록·`null`)이다 (대안: 배포 직후 `global` 켬; 이유: 켜는 순간 서로 다른 저장소 정책(§2 switch 12·wait 5)을 한꺼번에 덮는다). 그래서 **배포 뒤 사용자가 켤 때까지 전역 로그인 자동 전환(Claude UI-btp3, Codex UI-tyc2)은 멈춘다**. 수동 전환과 저장소별 Worker 전환은 그대로다.
- 결정 — **끔이면 전역 로그인 자동 전환 없음**: `repo`인 러너의 활성 전환 패스는 판정하지 않는다. 저장소 정책을 빌리는 지금 규칙(switch 허용 목록 순회, 기다림 보호, 보류 알림)은 지운다 (대안: 끔일 때 지금 규칙 유지; 이유: 사용자 결정).
- 결정 — **켬의 전역 로그인 판정**: 전역 정책이 `switch`이고 허용 목록에 활성 계정과 후보가 함께 있을 때만 바꾼다. 트리거 사용량은 `preempt_pct`가 있으면 그 값, 없으면 100이다. 후보는 공급자별 현행 규칙에, 판정 창이 모두 트리거 미만이어야 한다는 조건을 더한다 (대안: 전역 로그인은 언제나 100%; 이유: 같은 블록의 `선제 전환`이 Worker에만 먹고 전역 로그인에는 안 먹으면 이번에 고치려는 어긋남이 다시 생긴다. 기본은 꺼짐이라 11-07의 100% 동작이 유지된다). Claude 판정 창은 지금처럼 5h·7d뿐이다.
- 결정 — **기다림 보호 없음**: `global`이면 모든 저장소가 같은 모드라 기다림 저장소와 전역 전환이 충돌하지 않고, `repo`면 전역 전환이 없다. 앞서 정한 "기본 계정 없는 기다림 저장소 경고"는 이 구조에서 필요 없어 두지 않는다.
- 결정 — **유지하는 안전장치**: 공급자 잠금 아래 확정 재판정, 한 번에 한 패스, 보류 계정·실행 중 계정 제외, Claude `sessionLoginOwn` 예외, Codex `accountless_run` 거름, Claude 전환 직후 오류 귀속은 UI-btp3 그대로다.
- 결정 — **바뀐 값의 반영**: 전역 설정 쓰기가 성공하면, 저장소 정책을 바꿨을 때와 같은 `reevaluateWorkerProviderSwitches`를 등록된 모든 저장소에 부르고, 활성 전환 패스에 한 번 판정을 맡긴다. 실행 중 attempt는 반응하지 않는다(UI-np4t 조항 유지).
- 결정 — **전역 적용 중 저장소 화면**: `global`인 러너의 저장소 `한도 대응` 행(저장소 창·일괄 창)은 비활성·흐림으로 그리고 한 줄 안내 `전역 적용 중 — 모니터 ⚙ 전역 탭에서 바꿉니다`를 단다. 저장된 값은 보이되 고칠 수 없다 (대안: 계속 편집 가능; 이유: 고쳐도 반영되지 않는 값을 편집하게 두면 이번 혼동이 남는다).

### 4.2 전역 설정 저장과 채널

예: `server/limit-policy-settings.js`가 `$XDG_STATE_HOME/bdui/limit-policy-settings.json`을 소유한다. 모양은 `{ revision, runners: { claude: { scope, mode, accounts, preempt_pct }, codex: {…} } }`이다. timing-settings 선례를 따른다:
- 읽기는 fail-quiet다. 파일이 없거나 깨졌으면 초기값을 쓴다. 러너 하나가 틀리면 그 러너만 초기값으로 돌리고 로그를 한 줄 남긴다. 깨진 파일은 `repo`로 읽히므로 전역 덮어쓰기도 자동 전환도 일어나지 않는다.
- 쓰기는 엄격하다. `revision` CAS를 쓰고, 거절하면 아무것도 쓰지 않는다. 오류 코드는 `conflict`·`invalid_value`다.
- WS 구독·쓰기 채널 한 쌍과 프론트 싱글턴 스토어를 둔다. 저장소 창·일괄 창도 `scope`를 읽어야 하므로 앱 시작 때 구독한다.
- 서버 소비자는 판정 시점에 동기 getter로 현재 값을 읽는다.

### 4.3 실효 정책 소비자

예: `effectiveLimitPolicy(stored, runner)` — `global`이면 전역 정책, 아니면 정규화한 저장소 정책을 돌려준다.

| 소비자 | 바뀌는 것 |
| --- | --- |
| 스케줄러 `providerLimitPolicyOf` | 실효 정책을 돌려준다 (호출부 6곳은 그대로) |
| 큐 저장소 `auto_switch` 판정·기다림 추종 대상·보류 멤버 전환 쓰기 | 쓰기 안에서 실효 정책을 읽는다 |
| 세션 Codex 후보 조회 API | 실효 Codex 정책 |
| 활성 전환 패스(Codex·Claude) | §4.4 |
| 저장소 창·일괄 창 `한도 대응` | 저장 값을 그리되 `global`이면 §4.1대로 잠근다 |
| 일괄 창 저장소 행 | 저장 값을 그대로 싣는다 (복사 원천이라 실효 값이 아님) |

### 4.4 활성 전환 패스

공유 흐름은 그대로 두고, 저장소 순회 대신 전역 설정 하나를 입력으로 받는다.
1. 러너가 `repo`이거나 전역 `mode`가 `wait`이거나 허용 목록이 비었으면 판정을 끝낸다. 타이머 규칙은 지금과 같다(Claude 상시, Codex는 트리거 관측 중에만).
2. 활성 행의 판정 창 중 하나가 트리거 이상이 아니면 끝낸다.
3. 활성이 전역 허용 목록에 없으면 바꾸지 않는다 — 소진 계정을 일부러 활성으로 두려면 목록에서 뺀다.
4. 보류·실행 중 계정을 빼고 공급자 규칙으로 후보를 고른다. Codex는 허용 목록의 사용자 순서, Claude는 주간 사용률이 낮은 순이다.
5. 잠금을 쥐고 새 목록과 새로 읽은 전역 설정·보류·실행으로 다시 판정한 뒤 수동 전환 경로로 바꾼다.

### 4.5 보이는 것

모니터 ⚙ `전역` 탭에 `한도 대응` 절을 하나 더한다. 러너마다 묶음 하나이고 행 순서는 다음과 같다.
- `적용 범위` — `.op-btn` 분할 버튼 `저장소별 / 전역`. 아래에 한 줄 안내: `전역: 모든 저장소의 Worker와 Mac 전역 로그인이 아래 값을 따릅니다 · 저장소별: 각 저장소 설정을 쓰고 전역 로그인은 자동으로 바꾸지 않습니다`.
- `대응 방식`·`전환 허용 계정`·`선제 전환` — 저장소 `한도 대응` 블록과 같은 행·부품·순서다(Codex 순서 있는 허용 목록 포함). 같은 템플릿으로 그리고 손으로 다시 조립하지 않는다. `저장소별`이면 이 세 행은 흐리게 그리되 편집은 할 수 있다.

알림(`ops`):
- Claude: `🔁 Claude 전역 로그인 자동 전환 — 계정 #3 → 계정 #4` / `#3 5h 100% · 전역 한도 대응 · 실행 중 세션도 곧 새 계정을 씁니다`
- Codex: `🔁 Codex 전역 로그인 자동 전환 — 계정 #3 → 계정 #1` / `#3 5h 100% · 전역 한도 대응 · 새로 시작하는 호출부터 적용`
- 보류 알림(`⏸ … 보류 — 기다림 저장소 …`)은 없어진다.

### 4.6 오류와 경계

- 전역 설정 읽기 실패 → `repo`로 읽는다. Worker는 저장소 정책을 쓰고 전역 로그인은 바뀌지 않는다.
- 전역 허용 목록에 카탈로그에 없는 계정이 있으면 → 저장소 블록과 같이 따로 표시하고 순서를 유지한다. 판정에서는 후보가 될 수 없다.
- `global`로 켠 순간 보류 중인 attempt → 재평가가 새 실효 정책으로 전환·추종을 판정한다.
- 서버 재시작 → 파일에서 다시 읽는다. 메모리 상태는 Claude 전환 직후 귀속 기록뿐이다(UI-btp3와 같음).

### 4.7 테스트 범위

- 전역 설정 모듈: 파일 없음·깨짐 → 초기값, 러너 하나만 틀림, CAS `conflict`, `invalid_value`에 무쓰기.
- 실효 정책: `global` → 전역 값, `repo` → 저장소 값.
- 스케줄러·큐 저장소: 저장소 `switch`라도 전역 `wait`이 켜져 있으면 `auto_switch: 'disabled'`, 그 반대도 확인. 기다림 추종 대상 판정.
- Codex 후보 조회 API: 실효 정책을 읽는다.
- 활성 전환: `repo`면 저장소 허용 목록이 있어도 바꾸지 않는다. `global`·`switch`면 기본 계정 없는 wait 저장소가 있어도 바꾼다. `preempt_pct` N에서 트리거한다. 후보가 N 이상이면 고르지 않는다. 새 알림 문구. `accountless_run` 유지.
- WS: 전역 쓰기 성공이 등록 저장소마다 재평가를 부른다.
- UI: `전역` 탭 절의 행·순서, `global`일 때 저장소 창·일괄 창의 잠금과 안내.

### 4.8 수용 기준

- Claude·Codex 각각 `적용 범위`를 바꾸면 다음 판정부터 모든 저장소의 보류 카드와 전환이 그 범위의 정책을 따른다.
- `저장소별`인 러너의 전역 로그인은 사용량이 100%여도 자동으로 바뀌지 않는다.
- `전역`·`자동 전환`인 러너의 전역 로그인은 트리거 사용량에서 전역 허용 목록 안의 여유 계정으로 바뀌고, 알림에 `전역 로그인`과 `전역 한도 대응`이 보인다.
- `전역`을 껐다 켜도 저장소 정책 값은 그대로다.

## 5. 결정 (ADR 후보)

- 전제: ADR UI-btp3 — 공유 활성 전환 흐름·잠금·확정·전환 직후 귀속·공급자별 후보 규칙을 따르고, 정책 기준·기다림 보호·고정 100% 트리거 조항만 바꾼다.
- 전제: ADR UI-5cmo — 새 조작은 스펙이 슬롯을 정한 뒤 단다. §4.5가 `전역` 탭 절의 행 순서를 정한다.
- 한도 대응의 러너별 전역 적용 스위치와 전역 로그인 자동 전환의 기준 — 되돌리기 어렵다: 스케줄러·큐 저장소 판정·활성 전환 패스·후보 API·설정 화면·알림이 함께 움직인다. 대안이 실재한다: 저장소 정책 빌리기(현행), 켤 때 복사, 전역 로그인 고정 100%. 맥락 없이는 놀랍다: 저장소에 저장한 값이 반영되지 않을 수 있고, 배포 뒤 전역 로그인 자동 전환이 꺼진 채 시작한다. 소비자 집합이 UI-btp3와 같아 이를 대체하고 조항 전부를 다시 적는다. `summary`: "한도 대응에 러너별 서버 전역 정책과 적용 범위 스위치를 두어, 전역이면 모든 저장소의 그 러너 Worker 판정과 전역 활성 계정 자동 전환이 전역 정책(저장소 값은 보존)을 따르고 저장소별이면 저장소 정책만 쓰며 전역 활성 계정은 자동으로 바꾸지 않고, 전역 활성 계정 전환은 전역 허용 목록과 선제 전환 임계(없으면 100%) 미만 후보로 판정하며 기다림 보호를 두지 않는다 — 나머지 조항은 UI-btp3 그대로다" → ADR, supersede UI-btp3
- 알림 문구를 `전역 로그인 자동 전환`으로 바꾼다 — 기본 제외 목록(문구·표시) → ADR 아님
- 전역 적용 중 저장소 `한도 대응` 행을 잠근다 — 되돌리기 쉬운 화면 동작으로 소비자가 설정 창뿐이다 → ADR 아님
