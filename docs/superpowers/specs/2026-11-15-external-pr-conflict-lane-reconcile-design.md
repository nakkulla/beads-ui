# 외부 PR 충돌 해소 전에 일반 대기줄을 정리한다 (UI-rbk7)

## 1. 목표

이미 PR이 있는 Bead는 일반 작업 대기줄의 맨 앞·중간 어느 위치에 있든 충돌 해소를
시작할 수 있어야 한다. 대기줄과 PR 등록 사이의 불일치를 먼저 정리하고, 실행 중인
작업·중복 시작·직렬 실행 자리의 점유는 기존 보호 규칙으로 막는다.

이 문서는 구현 전 설계다. 이슈 본문의 권고안을 채택한 초안이며, 구현 진입 답변 전에는
코드를 바꾸거나 구현 작업을 시작하지 않는다.

## 2. 검증된 전제

조사 기준: `de28f838fbf7a5b6f5828787271741c08ce1dbc4`.

- 외부 PR 등록은 실행 소유 집합을 제외하지만 일반 대기줄 항목의 이동을 함께 실행하지 않는다 — server/worker/attach.js:1813, 2025-2065.
- 외부 PR 관측기는 별도 단계에서 PR 대기 이동을 호출하며 반환값을 검사하지 않는다 — server/worker/pr-poller.js:557-570.
- PR 대기 이동은 일반 병렬·직렬 대기 항목이 있고 모든 attempt가 종료 상태일 때 한 저장소 쓰기로 항목을 옮긴다. 이미 PR 대기·완료에 있거나 처분 작업이 진행 중이면 이동하지 않는다 — server/worker/queue-store.js:12386-12433.
- 이동 결과의 `ok: false`는 실패 원인을 구별하지 않는다. 두 번째 이동 호출도 `false`다 — server/worker/queue-store.js:12386-12433; server/worker/queue-store.test.js:12735-12747.
- 최초 외부 충돌 해소는 외부 PR 등록을 확인하지만 PR 대기 이동 없이 lane `null`로 시작·재검사한다 — server/worker/scheduler.js:19565-19603, 19726-19753.
- 외부 PR 등록 행에는 `pr_url`은 있지만 `head_ref`는 없다. head branch는 호출자의 PR 관측값이 기존 dispatch 인자로 전달된다 — server/worker/external-pr.js:25-54, 166-198; server/worker/pr-actions.js:3991-4007; server/worker/scheduler.js:19565-19572.
- 반복된 외부 충돌은 이전 외부 해소 attempt를 찾아 공통 재실행 경로를 사용한다 — server/worker/scheduler.js:19514-19524, 19630-19646.
- 시작 보호는 요청 lane과 현재 실행 lane이 다르면 `serial_lane_not_head`로 거절한다. 실행 lane은 대기줄이 없으면 같은 Bead가 보유한 직렬 자리를 따른다 — server/worker/scheduler.js:1147-1152, 6501-6549.
- 종료 상태 목록은 `running`·`paused`를 포함하지 않고 `failed`·`orphaned`·`waiting` 등을 포함한다 — server/worker/queue-store.js:2356-2376.
- PR 대기 이동은 이전 직렬 lane을 항목에 남기며, 기존 테스트가 병렬 이동·실행 중/일시정지 거절·반복 호출을 검증한다 — server/worker/queue-store.js:12422-12431; server/worker/queue-store.test.js:12627-12748.
- PR 대기의 직렬 점유는 최근 attempt의 유효 lane을 우선하고 없으면 PR 대기 항목의 lane을 따른다. 머지 보류 선반에 있는 항목은 이 fallback 점유에서 제외한다 — server/worker/queue-store.js:2542-2553.
- 거절 문구 변환기는 모르는 이유 코드도 원문으로 반환한다 — app/views/worker/pr-wait-row.js:165-168.
- 공유 서비스 배포는 저장소의 `[deploy]` 선언이 담당한다 — repo-ops/config.toml:26-28.

## 3. 선택과 범위

결정: 외부 PR의 충돌 해소는 일반 구현 대기줄의 순번을 기다리는 작업으로 취급하지 않는다.
시작 전에 일반 대기줄을 PR 대기로 옮기되, 실행 소유권과 직렬 자리 점유 검사는 유지한다.

검토한 대안:

- 현재 대기 lane을 넘겨 맨 앞에서만 시작: 일반 구현 순서는 보존하지만 이미 배달된 PR이 뒤쪽에서 막힌다.
- continuation으로 검사만 면제: 대기줄에 같은 Bead가 남아 일반 dispatch와 충돌 해소가 다른 상태를 본다.
- PR 대기로 먼저 이동: 기존 이동 기능과 PR 생명주기를 따른다. 이동 불가·반복 호출·실행 직전 경쟁을 구별해야 한다. 이 안을 채택한다.

같은 저장소의 한 구현 단위로 닫는다. 새 하위 시스템·외부 계약·상태 스키마를 만들지 않는다.
UI-qyr9의 Codex fork 실행 인자와 시작 감시는 다루지 않는다. UI-yig0의 세션 소유 외부
대기 재개 규칙과 일반 작업의 직렬 순번 규칙도 변경 대상이 아니다.

## 4. 동작

### 4.1 시작 전 정리

외부 PR 충돌 해소의 최초 시작과 반복 시작 모두 같은 준비 조건을 만족해야 한다.

1. 기존 슬롯·처분·중복 실행 보호와 외부 PR 등록을 확인한다.
2. 일반 대기줄에 남은 Bead만 기존 PR 대기 이동 기능을 호출한다. URL은 외부 PR 등록의
   `pr_url`, head branch는 호출자가 PR을 관측해 넘긴 기존 `head_ref` 인자를 사용한다.
   일반 대기줄에 있는데 둘 중 하나가 없으면 시작하지 않는다. 브랜치를 Bead ID로 추정하지 않는다.
3. 반환값 하나로 성공을 추정하지 않고 새 스냅숏에서 일반 대기줄 부재·PR 대기 존재와
   소유권을 확인한다. 다른 호출이나 관측기가 먼저 옮긴 경우도 이 조건을 만족하면 성공이다.
4. 처음부터 일반 대기줄에 없고 PR 대기에 있는 Bead는 그대로 진행한다. 어느 대기줄에도
   없는 기존 외부 PR도 계속 시작할 수 있다. 완료 항목은 시작하지 않는다.

이동 판정과 이동 자체는 기존 저장소의 원자적 쓰기가 소유한다. 스케줄러가 항목을 직접
지우고 별도 쓰기로 PR 대기에 추가하는 방식은 사용하지 않는다.

### 4.2 이동하지 못했을 때

결정: 비종료 attempt를 자동 종료하거나 대기줄 배치를 강제로 철회하지 않는다.

- `running` 또는 진행 중인 시작 예약이 있으면 기존 `bead_running`으로 거절한다.
- `paused`를 포함한 다른 비종료 attempt 때문에 이동할 수 없으면
  `external_pr_attempt_not_terminal`로 거절한다. 종료 여부는 기존 저장소의 종료 상태 정의를 따른다.
- 처분 작업은 기존 `discard_in_progress`, 외부 PR 등록 부재는 기존 `not_external`로 거절한다.
- 완료 항목은 `external_pr_already_done`으로 거절한다.
- 필요한 PR 관측값 부재, 저장 예외, 또는 원인을 구별한 뒤에도 일반 대기줄이 남아 있으면
  `external_pr_reconcile_failed`로 거절한다. 조사 가능한 로그에 원인을 남긴다.

위 거절은 새 runner, attempt, 실행 metadata를 만들지 않는다. 일반 대기줄은 이동이 실제로
성공한 경우에만 달라진다. 이동 전 거절은 기존 위치를 보존한다.

### 4.3 시작 예약과 실행 직전 재검사

최초 시작은 정리 후의 새 스냅숏으로 기존 실행 lane 해석을 적용한다
(예: `dispatchLaneOf`). 대기줄을 벗어난 뒤에도 같은 lineage가 직렬 자리를 보유하면
그 자리를 물려받고, 보유한 자리가 없으면 lane 없이 시작한다. PR 대기에 보관된 직렬 lane도
기존 점유 판정의 입력이므로 지우거나 무시하지 않는다. 다른 lineage가 그 자리를 점유 중이면
순번 오류 대신 기존 `serial_lane_occupied`로 거절한다. 선반에 둔 항목의 점유 예외도 유지한다.

반복 시작은 기존 이전 attempt 기반의 재실행·설정 판정을 유지한다. 준비 단계가 그 판정을
우회하거나 최초 시작으로 바꾸지 않는다. 기록하는 lane은 최종 시작 검사가 승인한 lane이다.

비동기 준비 뒤, 첫 guard/attempt/실행 metadata 변경 직전에 다음을 동기로 다시 확인한다.

- 외부 PR 등록이 남아 있고 완료·처분·다른 비종료 작업이 생기지 않았다.
- 일반 대기줄에 다시 배치되지 않았다. 다시 배치됐다면 동일한 이동 규칙으로 정리하거나
  그 원인의 거절을 반환한다. 일반 대기줄이 남은 채 launch하지 않는다.
- 기존 시작 예약을 재검사하고, 같은 Bead의 중복 시작과 다른 lineage의 직렬 점유를 거절한다.

재검사부터 durable attempt 기록까지 await를 넣지 않는다. 반복 시작의 종료된 이전 attempt는
새 실행으로 오판하지 않되, 준비 중 새로 생긴 비종료 attempt는 거절한다.
동시 클릭 두 번은 시작 예약·attempt 기록이 한 번만 성공해야 한다.

### 4.4 시작 이후 실패

PR 대기 이동은 외부 PR이 이미 배달됐다는 사실을 반영한다. 이후 설정 확인·guard 설치·
attempt 기록·runner 시작이 실패해도 일반 대기줄로 되돌리지 않는다. PR 대기에서 같은
충돌 해소를 다시 요청할 수 있어야 한다. 기존 실패 attempt·metadata 복구·예약 해제 규칙은 따른다.
다른 Bead의 순서, 직렬 자리 점유, 머지 대기열과 보류 상태를 추가로 변경하지 않는다.

## 5. 검증과 수용 기준

구현 시 기존 실제 queue-store를 사용하는 scheduler 테스트를 중심으로 아래 동작을 검증한다.
구현 전인 이 작성 세션에서는 런타임 테스트를 실행하거나 코드를 변경하지 않는다.

- 직렬 맨 앞과 중간, 병렬 대기줄 각각에서 외부 PR을 PR 대기로 옮기고 충돌 해소를 한 번 시작한다.
- 이동은 다른 Bead의 상대 순서를 보존하고 PR URL·head 및 기존 직렬 출처를 보존한다.
- 이동 뒤 PR 대기 항목의 직렬 출처를 기존 점유 규칙대로 읽고, 다른 lineage가 같은 자리를 점유 중이면 `serial_lane_occupied`로 거절한다. 선반 항목의 기존 점유 예외도 유지한다.
- 종료된 일반 attempt가 자기 직렬 자리를 보유하면 그 자리를 물려받는다. 같은 자리를 다른 lineage가 점유한 경우 기존 점유 거절을 유지한다.
- `running`은 `bead_running`, `paused`와 그 밖의 비종료 상태는 지정한 이유로 거절하고 위치·attempt·실행 metadata를 보존한다.
- 이미 PR 대기인 경우, 처음부터 무소속인 외부 PR, 관측기가 먼저 이동한 경우 모두 기존 시작을 허용한다.
- 최초·반복 해소 모두 준비 조건을 적용한다. 반복 해소의 이전 세션·설정·lane 선택 동작을 보존한다.
- 처분·완료·PR 등록 소실·필수 관측값 부재·저장 예외를 각각 실제 원인으로 거절하고 새 실행을 만들지 않는다.
- 비동기 준비 중 재배치·비종료 attempt 추가·처분 시작·PR 등록 소실을 주입해 마지막 검사에서 막는지 확인한다.
- 동시 클릭 두 번은 runner와 새 attempt가 각각 한 번만 만들어진다.
- 이동 성공 후 guard/attempt 기록/runner 실패는 PR 대기를 유지하고 예약을 해제하며 재시도를 허용한다.
- pr-actions 경로에서 새 거절 이유가 호출자까지 보존되는지 검증한다. 저장소의 기존 반복 이동·비종료 거절 테스트도 유지한다.

검증 묶음: 변경 파일 포맷, `npm run tsc`, `npm run lint`, `npx vitest run --reporter=dot`.
새 구현 worktree는 Node engines 확인과 `npm ci`를 선행한다. 서비스 반영은 구현 PR이
머지된 뒤 기존 `[deploy]`가 담당하고 프로세스 경로·포트·HTTP 응답 증거를 남긴다.
이 스펙 작성·리뷰는 구현·머지·서비스 재시작 권한을 부여하지 않는다.

## 6. 결정 (ADR 후보)

- 전제: ADR UI-ny0h — PR 머지는 Worker 단일 큐가 담당하고 충돌 해소의 슬롯·수동 권한 판정은 유지한다.
- 외부 PR 충돌 해소 전에 일반 대기줄을 PR 대기로 정리한다 — 기존 저장소 이동 기능을 한 dispatch 경로에 연결하는 동작 수정이며 함께 전환할 외부 소비자가 없어 되돌리기 쉽다 → ADR 아님
- 비종료 attempt는 보존하고 실제 거절 원인을 반환한다 — 기존 소유권 보호를 적용하는 국소 수정이라 되돌리기 쉽다 → ADR 아님

## 7. 경계·후속

없음 — 필요한 구현·테스트와 기존 배포 경로가 이 저장소 안에서 닫힌다.
동시 진행 UI-qyr9와는 파일이 겹칠 수 있으나 이 설계가 그 결과를 전제로 소비하지 않으므로
선행 의존을 만들지 않는다. 같은 UI-rbk7의 다른 세션은 이 spec_id와 리뷰 기록을 이어받는다.
