# UI-mscc — 부모 부분 비용 복원과 부모·자식 최종 사용량 합산

상태: 사용자 검토용 초안. 2026-09-15 대화에서 부모·자식의 직접 사용량을 각각 한 번씩 합산하고 불완전한 값은 부분 집계로 표시한다는 방향을 확인했다. 이 문서의 승인과 구현 진입은 아직 기록하지 않았다.

## 1. 목표와 확인된 원인

부모의 확인된 사용량에 모델 단가를 적용하고, 연결된 자식의 직접 사용량까지 포함한 총액을 카드·상세·비교 화면에서 같은 기준으로 보여 준다. 사용량의 귀속, 가격을 계산할 수 있는지, 관측이 완전한지는 서로 다른 판단이다.

UI-pqel의 저장된 부모 구간에는 `model=astra`, `usage.replayed=true`, `partial=true`가 함께 있다. `app/utils/token-usage.js`의 `sumAttemptUsage`는 `partial=true`이면 모델을 가격 계산에 전달하지 않는다. 설정에는 astra 단가가 있어도 `Codex τ 2.5M · 단가 없음`이 된다. 실제 저장값을 바꾸지 않고 이 조건만 제거한 재현에서는 `$3.96`이 나왔다.

합산에 관한 기존 결정은 ADR UI-42l2다. 부모·자식의 중복 관계를 확인하지 못해 native child를 총합에서 제외했다. 이번 조사에서는 UI-pqel의 Codex 0.154.0 원본 기록을 대조했다.

| 관측 범위 | 고유 응답 수 | 입력 | 캐시 입력 | 출력 | 입력+출력 | 현재 설정 단가 환산 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 부모 직접 사용량 | 29 | 2,442,197 | 2,339,968 | 11,953 | 2,454,150 | $3.959908 |
| 자식 직접 사용량 | 3 | 86,154 | 29,440 | 1,085 | 87,239 | $0.650830 |
| 중복 제거 후 합계 | 32 | 2,528,351 | 2,369,408 | 13,038 | 2,541,389 | $4.610738 |

두 파일의 `response_id` 교집합은 0이고, 각 파일의 응답별 `usage` 합은 마지막 `thread_token_usage`의 모든 토큰 필드와 일치한다. 모든 응답의 `thread_id`도 해당 파일의 자기 대화 ID와 일치한다. 부모와 자식이 공유하는 `session_id`와 `root_turn_id`는 직접 사용량의 중복 제거 키가 아니다. 서버 재시작 복구 표시가 남아 있으므로 위 환산액은 관측된 부분 비용의 재현값이며 전체 청구액의 증거가 아니다.

재현 원천은 부모 대화 `01a0a15e-2409-7db2-b2ba-98a6323f3314`의 응답 기록 29개와 마지막 기록 242행, 자식 대화 `01a0a162-a541-7c52-8d04-21e2d25144f4`의 응답 기록 3개와 마지막 기록 35행이다. 경로는 기존 계정별 세션 경로 해석기로 찾는다. 전사 본문·계정 정보·원문 경로는 테스트 fixture나 UI payload에 복사하지 않는다.

공개 Codex 소스도 응답별 기록과 누적 스냅샷을 구분한다. 조사 시점의 정본은 커밋 `b9bfc0aff84de6af4c549f1ae544de569474f5f4`의 [TokenUsageRecord](https://github.com/openai/codex/blob/b9bfc0aff84de6af4c549f1ae544de569474f5f4/codex-rs/protocol/src/protocol.rs#L2253) 및 [exec 누적 사용량 출력](https://github.com/openai/codex/blob/b9bfc0aff84de6af4c549f1ae544de569474f5f4/codex-rs/exec/src/event_processor_with_jsonl_output.rs#L117)이다. 이는 설치된 바이너리와 같은 빌드라는 증거는 아니므로 실제 기록의 대조와 함께 사용한다. 모든 버전의 부모 누적값이 항상 자식을 제외한다고 일반화하지 않는다.

## 2. 선택한 방식과 대안

응답별 직접 사용량을 기존 관측기 안에서 중복 제거해 모델별 구간으로 접고, 공용 사용량 투영에서 부모·자식을 합산한다. 기록에 있는 ID와 경계를 사용하므로 재시작·재개·자식 재사용에서도 같은 소비를 두 번 더하지 않을 수 있다. 별도 회계 서비스나 가격 저장소는 만들지 않는다.

기존 부모·자식 누적 숫자를 그대로 더하는 방식은 코드가 적지만, 재개된 자식의 이전 사용량과 외부 영수증으로도 관측된 실행을 중복 계산할 수 있다. 기존 합산 제외를 유지하면 중복은 피할 수 있지만 사용자가 요청한 최종 총액을 제공하지 못한다. 두 대안은 채택하지 않는다.

한 저장소의 사용량 관측→집계→표시가 함께 바뀌는 하나의 설계이며, 한 구현 단위에서 통합 검증한다. 경로 수 때문에 독립 Phase로 나누지 않는다.

## 3. 직접 사용량의 원천과 중복 제거

### 3.1 응답 기록을 기존 구간으로 정규화

- 원천은 해당 attempt의 부모 rollout과 부모 연결이 그 root까지 확인된 자식 rollout이다. 기존 계정 격리와 대화 경로 해석을 사용한다.
- `token_usage_record.payload.usage`를 응답별 직접 사용량으로 읽는다. 같은 `response_id`가 다시 나타나면 한 번만 기여한다. 같게 재생된 기록은 무시하고, 같은 ID가 서로 다른 소유자·수치를 주장하면 해당 기여를 확정하지 않고 집계 불완전 사유를 보존한다.
- 관측기는 `thread_id`, `turn_id`, 그 turn에서 실제 관측된 모델, 응답 시각을 함께 유지한다. 모델 변경 전후 구간을 나눈다. 마지막 모델이나 부모 모델로 다른 구간의 가격을 대신 계산하지 않는다.
- 응답별 값을 기존 `usage_segments` 및 자식 관측 구간으로 접는다. 서버에는 합산 가능한 직접 기여와 그 범위·원천을 저장하고, 프런트에는 집계에 필요한 구간만 전달한다. 원문 전사와 응답 ID 전체 목록을 카드 payload나 `queue.json`에 복제하는 별도 원장은 만들지 않는다.
- `turn_token_usage`, `thread_token_usage`, `token_count`, `turn.completed.usage`는 응답별 기여 위에 추가로 더하지 않는다. 누적값은 관측 누락 및 범위를 확인하는 대조값이다. 특히 공개 exec의 `turn.completed.usage`를 매 turn의 새 소비로 더하지 않는다.
- 응답별 원천이 없는 과거 형식은 기존 토큰 표시를 보존한다. 자기 대화의 직접 누적값 및 attempt 경계가 입증되는 경우에만 baseline 차이로 합산 가능한 구간을 만든다. 직접 귀속이나 경계를 알 수 없는 값은 개별 관측으로 남기고 전체 합계의 누락 사유로 설명한다.

### 3.2 attempt 경계와 동일 실행의 여러 표현

- Worker 집계는 해당 attempt의 시간·turn 경계 안에서 실제 발생한 소비만 포함한다. 새 attempt에 재사용된 자식은 이전 누적값 전체가 아닌 그 이후의 응답 또는 검증된 baseline 차이만 기여한다.
- 연속 attempt의 경계는 같은 응답을 양쪽에 넣지 않는다. timestamp만으로 소유자를 가를 수 없는 경계 충돌은 원래 실행/turn 연결 증거로 해소하며, 해소되지 않으면 미확정 기여로 남긴다.
- native child와 외부 `usage_legs`가 같은 대화·turn·범위를 나타내면 한 번만 합산한다. 응답으로 검증된 직접 구간을 우선하고 그 범위와 겹치는 영수증의 비용은 이미 포함된 것으로 취급한다. 영수증이 더 넓은 범위일 때는 입증된 비중복 차이만 추가한다. 겹치는 범위를 분리할 수 없으면 부분 집계 사유를 남기고 중복될 수 있는 전체 영수증을 더하지 않는다.
- 이름·모델·토큰 숫자가 같다는 이유로 동일 실행으로 판단하지 않는다. 대화 ID나 영수증 ID처럼 실제 실행 연결을 입증하는 키를 사용한다.
- 같은 attempt 스냅샷의 반복, 같은 자식의 여러 wait/send, 자식의 자식은 고유 실행과 범위별로 한 번만 기여한다. 여러 attempt의 합산에서도 이미 사용한 기여를 다시 세지 않는다. 구현에서 선택한 구간 식별자는 이 성질을 테스트로 증명한다.
- Claude의 기존 부모 보고 비용에 이미 포함된 subagent 비용 처리와 `cost_covered` 의미는 유지한다. Codex native child를 합산하는 변경을 Claude의 보고 비용에 일괄 적용하지 않는다.

## 4. 모델·가격·완전성

`partial` 또는 `replayed`라는 이유만으로 확인된 모델을 지우는 조건을 제거한다. 해당 토큰 구간의 모델이 확인되면 기존 `priceUsage`로 비용을 계산한다. 모델이 미확정인 구간은 토큰을 보존하고 가격은 미확정으로 남긴다.

부분 집계의 원인은 모델 미확정, 누락된 사용량, attempt 경계 미확정, 겹침 미해소를 구분한다. 모델이 확인된 부분 비용을 계산할 수 있어도, 귀속 경계가 불명인 값은 attempt 총액에 넣지 않는다. `replayed` 표시만으로 모델 불명이나 중복을 뜻하지 않는다.

부분 여부는 구간→provider→attempt→Bead→워크스페이스/비교 합계까지 전파한다. 자료가 없는 자식을 0원으로 만들지 않는다. 가격을 계산할 수 있는 부분은 표시하고, 가격 미확정 건수와 관측 누락을 함께 설명한다. 명시적 0원과 미확정을 구분한다.

가격은 현재 설정의 모델별 USD 환산 단가를 사용한다. Codex 캐시는 입력의 부분집합이고 추론 토큰은 출력의 부분집합이라는 기존 계산을 유지한다. 숫자는 반올림 전 값으로 합산하고 표시할 때 반올림한다. 새로운 단가·환율·계정 청구액 추정은 추가하지 않는다.

## 5. 화면과 소비자

- 카드의 기존 슬롯 5 사용량/비용 자리에 부모와 자식이 포함된 총합을 표시한다. 부모 단독 비용은 상세 분해와 사용량 설명에서 항상 확인할 수 있다. 자식의 개별 비용은 슬롯 3 위임 행 및 상세 자식 행에서 계속 표시한다.
- 합산된 카드의 `native child 비용 · 부모 합계 제외`는 `부모·자식 합계`로 바꾼다. 덜 관측된 카드에는 같은 자리에서 `부분 집계`를 함께 표시한다. 근거가 없어 자식 일부를 합산하지 못했다면 설명에 대상과 이유를 표시한다. 자료 없는 범위 설명은 그리지 않는다.
- 기존 카드 헤더 정본 §5.1의 슬롯 5를 `본체 usage/비용`에서 `부모·자식 합계 usage/비용과 집계 범위 설명`으로 정정한 뒤 렌더러를 바꾼다. 새로운 조작 버튼이나 클릭 동작은 추가하지 않는다.
- 부모/자식/총합의 값은 공용 투영 하나에서 나온다. Worker·Monitor의 실행/대기/완료 행, 상세의 attempt 및 Bead 총계, 비교 화면과 워크스페이스 비용이 같은 기여를 사용한다. 일반 비교와 벤치마크의 집계·중앙값도 부분 데이터 여부를 잃지 않으며 부분 금액을 완전한 비용으로 설명하지 않는다. 서버의 비교 투영뿐 아니라 `app/views/compare/format.js`의 비용 전달, `index.js`의 중앙값 표시, `bench-model.js`의 중앙값 재계산과 각각의 기존 테스트까지 같은 부분 집계 정보를 전달·검증한다.
- 직접 세션 카드에도 현재 참조 대화와 연결된 자식의 합계를 표시한다. 같은 직접 대화가 여러 Bead 카드에 나타나도 워크스페이스 비용에 가산하지 않는 ADR UI-42l2-2는 유지한다.
- `total_tokens`와 세부 토큰 수를 한 번씩만 센다. provider별 토큰 의미는 기존 규칙을 유지하며, USD 비용 합계와 토큰 소계는 구분한다.

## 6. 과거 이력·복구·종료

새 기록은 종료 시 기존 attempt 저장 경계에서 직접 사용량 구간과 집계 범위 증거를 함께 보존한다. 새 optional 필드는 정상화·저장·재읽기에서 유지되고, 부재한 과거 기록은 기존 표시로 읽힌다. 실시간과 재시작, 종료 직전 drain은 같은 누적 함수를 사용한다.

UI-pqel처럼 이미 끝난 이슈도 수정 후 부모의 가격과 합산 가능한 자식 비용이 표시되어야 한다. 저장된 모델의 가격 복원은 표시 시 즉시 반영한다. 합산 증거가 부족한 과거 attempt는 현재 표시/조회 대상의 정확한 세션 연결로만 기존 관측기를 사용해 보완한다. 원본이 있으면 응답을 재검증해 준비된 캐시에 반영하고 카드·상세·비교가 같은 결과를 받는다. 누락되면 확인된 부분만 표시한다.

과거 보완은 기존 구독/조회 준비 단계에서 비동기로 수행한다. 동기 카드 투영 안에서 전사 전체를 읽거나 추가 `bd` 프로세스를 실행하지 않는다. 계정 전체 전사를 무관하게 수집하거나 전체 이력을 한꺼번에 다시 쓰는 마이그레이션은 하지 않는다. 파일이 없거나 잘린 경우에도 이미 저장된 사용량을 0으로 덮지 않는다. 같은 파일/attempt를 동시에 요청해도 준비 작업은 공유하고 마지막 구독 해제 시 자원을 정리한다.

부모 완료와 자식 완료는 별개다. 성공·실패·중단 모두 실제 발생한 소비를 포함한다. 부모가 끝났어도 자식의 사용량 종료를 확인하지 못했다면 집계는 부분 상태다. 원본 terminal/drain 증거까지 확인한 경우에만 관측 범위가 완전하다고 표시한다.

## 결정 (ADR 후보)

- 전제: ADR 0012 — workflow metadata를 새로 정의하지 않고 UI 소유 관측 데이터만 확장한다.
- 전제: ADR 0014 — 공용 카드 렌더러와 슬롯 3·5를 사용하고 헤더 정본을 먼저 정정한다.
- 전제: ADR 0027 — 종료 사용량은 기존 attempt/Bead 이력 소유 경계에 보존한다.
- 전제: ADR 0043 — 동기 투영은 준비된 관측을 읽고 추가 전사 스캔이나 `bd` 조회를 하지 않는다.
- 전제: ADR UI-42l2-2 — 직접 대화는 현재 참조 범위로 표시하고 워크스페이스 합계에 자동 가산하지 않는다.
- 부모·자식의 검증된 직접 사용량을 각각 한 번씩 합산하고, 확인되지 않은 범위는 부분 집계로 표시한다. ADR UI-42l2의 관측 소유권·부모 연결 검증·자식별 표시·실제 수명 증거 규칙은 승계하고 무조건 합산 제외 조항을 대체한다. 되돌리기 어려움: 예(저장·표시·비교의 비용 의미가 함께 바뀜), 맥락 없으면 놀라움: 예(과거 합계가 자식 소비를 포함하도록 바뀜), 실제 절충: 예(검증과 부분 표시의 비용으로 중복 없는 합계 제공). `summary`: "부모와 자식의 검증된 직접 사용량을 중복 없이 합산하고 미확정 범위는 부분 집계로 표시한다" → ADR, supersede UI-42l2
- 모델 확인과 관측 완전성을 별개로 판정해 부분 구간에도 알려진 단가를 적용한다. 되돌리기 어려움: 아니오, 맥락 없으면 놀라움: 아니오, 실제 절충: 아니오 — 잘못 결합된 조건을 고치는 결함 수정이다 → ADR 아님

## 경계·후속

부모 가격 복원과 최종 합산은 같은 공용 사용량 경계의 UI-mscc 한 건으로 다룬다. 별도 형제·선행 Bead는 없다. 출처 UI-42l2는 `discovered-from` 관계이며 구현 선행 조건이 아니다. UI-pqel 자체의 크레딧 소진 분류 동작은 이 작업에서 바꾸지 않는다.

결정: 직접 세션을 Bead별 비용으로 배분하거나 워크스페이스 비용에 자동 가산하는 정책은 바꾸지 않는다 — 대화 안에서 Bead별 소비 경계를 증명할 수 없다는 기존 전제는 유지된다.
