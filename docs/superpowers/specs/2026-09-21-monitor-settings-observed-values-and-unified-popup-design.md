# 모니터 설정이 저장소의 현재 값을 드러내고 두 진입점이 같은 창으로 열린다

## 문서 상태

- Bead: `UI-e1ta`
- 경로: `spec_backed`; beads-ui 안에서 하나의 구현·검증·인도 묶음으로 처리한다.
- 기준: `main` / `1ae53bb3444a37357be087718ac0aae770c122df`
- 상태: 사용자 검토용 완성 초안. 구현·스펙 게이트 승인 전이다.
- 화면 미리보기: `http://100.122.98.8:9000/2026-09-21-monitor-settings-observed-values.html`
- 미리보기 파일: `~/tmp/mockups/2026-09-21-monitor-settings-observed-values.html`.
  저장하지 않는 설계 산출물이며 예시 저장소·계정·프리셋을 쓴다. 동작의 정본은 이
  문서이고 실제 모델·계정 목록은 설치된 카탈로그를 쓴다.

## 1. 사용자 결과와 확인한 원인

모니터 탭에서 설정을 열면 저장소들이 지금 무슨 값으로 도는지 그 자리에서 읽고,
바꿀 행만 고쳐 쓴다. 레포 카드에서 열든 헤더에서 열든 같은 창이 뜬다.

오늘 착지한 UI-628r이 여러 저장소 설정을 24키 편집면으로 넓히면서 "이 창은
저장소들의 현재 설정을 보여주는 화면이 아니다"를 함께 결정했다. 그래서
`bulk-worker-form.js`의 24행과 계정 탭 전체가 창을 열 때마다 `기본값 사용`에서
시작하고, 방금 일괄 적용한 값조차 다시 열면 남지 않는다. 같은 ADR이 일괄 모드
탭을 `워커`·`계정` 둘로 고정했고 프리셋 관리는 단일 저장소 창에만 두었다.

레포 카드 `⚙`는 덱 안에서 아래로 펼쳐지는 인라인 패널(`mon2-deck__panel`)이고
헤더 `⚙`는 다이얼로그다. 같은 탭의 같은 성격 조작이 두 형태로 열린다.

재료는 이미 화면에 있다. 모니터 행은 `session_defaults`(kv 18키),
`provider_limit_policy`, 큐의 오케스트레이션 6키, `execution_defaults`,
`runner_catalog`를 싣는다. 프리셋은 서버 한 벌이고 `impl-preset-create`·
`impl-preset-update`·`impl-preset-delete` 세 op는 `root_dir`을 받지 않는다.
`createExecutionPane`은 이미 `root_dir` 바인딩으로 다른 저장소를 편집한다.
계정 선택지가 읽는 `/api/claude-usage`·`/api/codex-usage`는 계정마다
`windows[].pct`를 함께 주는데 `fetchAccountProvider`가 `key`·`email`만 남기고
버린다. 저장소별 실행 계정(`claude_account`·`codex_account`)만은 모니터 행에
없고 `get-workspace-accounts`가 kv에서 읽는다.

즉 막고 있던 것은 기술이 아니라 UI-628r이 정한 화면의 역할이다. 이 설계는 그
역할을 바꾸고, ADR이 답이 없다고 본 지점 — 갈린 행의 초기값 — 에 답을 낸다.

## 2. 검토한 접근과 선택

1. **관측면 겸 편집면으로 바꾸고, 갈린 행은 값을 세우지 않는다**를 선택한다.
   선택한 저장소들의 현재 값을 읽어 채우되, 저장소마다 값이 다른 행은 값을
   만들어 내지 않고 `갈림`으로만 서며 사용자가 손대기 전까지 적용에서 빠진다.
   사용자 결정(2026-09-21): "갈림의 경우는 채우지 말고 갈려 있다고만 표시되어도
   되지 않나, 그리고 내가 그것을 프리셋이나 수동으로 선택한 다음 적용하면 되는
   것". 화면에 값이 선 행은 손대지 않아도 그대로 쓰인다는 UI-628r의 계약은
   그대로 남고, 갈림이라는 세 번째 상태만 새로 생긴다.
2. 갈린 행도 대표값(다수값·첫 저장소 값)으로 채우는 안은 기각한다. 읽는 사람이
   보지 못한 값이 화면에 서고, 손대지 않은 그 행이 소수 저장소를 덮는다.
3. 현재 값을 읽기 전용 요약으로만 덧붙이는 안은 기각한다. UI-628r을 건드리지
   않아 비용이 가장 낮지만 "보고 고치는" 화면이 되지 못해 요청을 채우지 못한다.

`갈림`은 `변경 안 함`의 부활이 아니다. `변경 안 함`은 사용자가 고르는 선택지로
모든 행에 있었고, `갈림`은 관측된 사실이라 사용자가 고를 수 없으며 값이 갈린
행에만 선다. 모든 저장소가 같은 값이면 `갈림`은 존재하지 않는다.

레포 카드 `⚙`는 헤더 `⚙`와 같은 다이얼로그를 그 저장소 단일 모드로 연다.
`createExecutionPane`이 이미 `root_dir`을 받으므로 pane을 다이얼로그 본문에
바인딩해 마운트하는 일이고, 덱 안의 패널 껍데기가 사라진다.

## 3. 관측 모델

`적용 대상`에서 고른 저장소 집합에 대해 각 키의 현재 값을 모아 행마다 하나의
상태를 정한다. 이 계산은 순수 함수로 두고(`bulk-observation.js`) 폼·계정 탭이
함께 쓴다.

| 관측 | 조건 | 화면 |
| --- | --- | --- |
| `같음` | 모든 저장소가 같은 비어 있지 않은 값 | 그 값이 선다 · `3곳 모두 같음` |
| `비어 있음` | 모든 저장소가 그 키를 두지 않음 | `기본값 사용`이 선다 · `3곳 모두 비어 있음` |
| `갈림` | 서로 다른 값이 둘 이상(빈 값 포함) | 값이 서지 않는다 · `갈림 · 2곳 high · 1곳 xhigh` |

`갈림` 배지의 `title`에는 저장소별 값을 전부 적는다. 저장소를 하나만 고르면
`갈림`은 나올 수 없고 배지도 달지 않는다.

`갈림` 행의 컨트롤은 선택지 맨 위에 `갈림 — 유지`가 선택된 채로 선다. 이 항목은
`갈림`일 때만 존재하고, 다른 값을 고르면 보통 행이 된다. 다시 고르면 관측으로
돌아간다 — 되돌리기 버튼을 따로 두지 않는다. 체크박스 집합인 `전환 허용 계정`만
컨트롤 모양이 달라 예외이며, 행 끝의 `↩ 갈림으로 되돌리기`가 같은 일을 하고
편집된 뒤에만 보인다.

### 3.1 편집 상태와 재계산

사용자가 고친 행은 `편집됨`으로 표시하고 관측 갱신이 덮지 않는다. `적용 대상`
선택이 바뀌거나 새 스냅샷이 오면 `편집됨`이 아닌 행만 다시 계산한다. 프리셋을
고르면 25행 전부가 `편집됨`이 된다. `갈림 — 유지`를 다시 고르면 그 행의
`편집됨`이 풀린다. 창을 닫으면 편집 상태는 사라진다 — 다음에 열면 다시 관측에서
시작한다.

### 3.2 적용

`[적용]`은 화면에 값이 선 행 전부를 선택한 저장소에 쓴다. `갈림`으로 남은 행은
payload에서 빠진다 — 그 저장소들의 현재 값이 그대로 남는다. `기본값 사용`은
값이므로 전송하고 그 키를 지운다(UI-628r의 의미 그대로). `갈림` 행이 있어도
`[적용]`은 잠기지 않는다.

두 탭의 배너는 새 계약을 말한다: `화면에 값이 선 행은 손대지 않아도 그대로
쓰입니다 — 갈림으로 남은 행만 저장소별 현재 값을 유지합니다.` 푸터는 그 회차에
빠지는 행 수를 적는다: `갈림 3행은 적용에서 빠집니다 · 나머지 21행을 저장소
3곳에 씁니다`.

저장소별 순차 호출, 저장소별 적용됨·부분 적용·실패 결과, 실패·부분 적용 저장소만
재적용, 계정 쓰기 실패 저장소에 정책 요청을 보내지 않는 규칙은 UI-628r 그대로다.

## 4. 워커 탭

행은 25개다. 기존 24키(kv 18 + 큐 6)에 `Bead 실행 방식`(`impl_dispatch`) 한
행이 더해진다. `impl_dispatch`는 워크스페이스 전역 저장이 없는 키(ADR 0012,
dotfiles 계약의 `user_write_only`)라 관측 대상이 아니고 적용 payload에도 넣지
않는다. 이 행은 프리셋에 담기 위해서만 있으므로 `기본값 사용`에서 시작하고
배지 자리에 `프리셋에만 담김 · 저장소에는 안 씀`을 단다.

그룹 구성(오케스트레이션·구현·리뷰 게이트·quick_fix)과 `session-model.js`의
옵션 계산 호출은 UI-628r 그대로다. 시스템 프롬프트는 여전히 범위 밖이다.

### 4.1 프리셋 관리

프리셋 바를 일괄 창에도 둔다: `[프리셋 select] [이름] [새 프리셋 저장 | 현재
설정으로 덮어쓰기] [삭제]`. 단일 저장소 창과 같은 세 op를 그대로 호출하고
`expected_revision`으로 경쟁을 판정한다. 프리셋은 서버 한 벌이라 `적용 대상`
선택과 무관하다.

- 고르면 25행이 그 프리셋 값으로 덮이고 프리셋이 비운 키는 `기본값 사용`이 된다.
- 저장은 화면의 25행을 그대로 담는다. `갈림` 행이 하나라도 있으면 담을 값이
  없으므로 **저장 버튼만** 잠그고 `갈림 N행을 먼저 정하세요`를 `title`에 쓴다.
  `[적용]`은 잠기지 않는다.
- 삭제는 고른 프리셋에만 걸린다.

단일 모드의 `현재 → 프리셋` diff 미리보기는 옮기지 않는다. 일괄 창에서는 폼이
곧 결과이고 관측 배지가 그 차이를 이미 말한다.

`적용된 프리셋` 한 줄을 프리셋 그룹 안에 둔다. 저장소별 `applied_exec_preset`
기록(`{ id, name, revision, applied_at }`, 큐 소유)을 같은 관측 규칙으로 읽어
`갈림 · 2곳 페이블 기본 · 1곳 없음`처럼 적는다. 이름은 기록이 담은 `name`을
그대로 쓰고 프리셋 목록을 다시 찾지 않는다. 읽기 전용이며 조작이 아니다. 기록을
세우고 푸는 판정은 서버가 소유한다. 이 기록은 모니터 행에 없으므로 §8의 투영에
함께 더한다.

## 5. 세션 탭

일괄 모드 레일에 `세션`을 더해 `워커`·`세션`·`계정` 세 탭이 된다. 단일 저장소
창의 세션 탭과 같은 세 행을 같은 관측 규칙으로 그린다.

| 행 | 키 | 값 |
| --- | --- | --- |
| 모드 | `workflow_mode` | `기본값 사용` · `standard` · `fast_track` |
| Worker 주소 | `bdui_url` | 저장소 defaults 문자열 또는 비움 |
| base 동기화 | `base_sync_accept_local_commits` | `켬` · `끔` |

`bdui_url`은 ADR UI-wecw의 저장된 값·적용값 분리를 따라 저장소 defaults만 읽고
쓴다. 공통 주소는 dotfiles 소유 CLI의 것이라 이 창이 건드리지 않는다.
`base_sync_accept_local_commits`는 계약이 `bool`로 두는 키이고 저장된 `false`와
부재가 같은 사실이므로 `기본값 사용`이 없는 두 값이다.

쓰기는 저장소마다 기존 `set-session-defaults`를 순차로 보낸다. 새 op는 없다.
`workflow_mode`가 프리셋에 담기지 않는 것(UI-7yh2 §3.7)은 그대로라 이 탭의 세
행은 프리셋과 무관하다.

## 6. 계정 탭

두 행의 실행 계정과 러너별 한도 대응을 현재 값에서 시작한다. 편집 항목 자체는
UI-628r 그대로이고 관측만 더해진다.

- `claude_account`·`codex_account`: 모니터 행의 새 `workspace_accounts`
  투영(§8)을 읽는다.
- 러너별 `대응 방식`·`전환 허용 계정`·`선제 전환`: 모니터 행이 이미 싣는
  `provider_limit_policy`를 읽는다.
- `전환 허용 계정`은 집합이라 하나라도 다르면 `갈림`이다. `갈림`이면 체크박스를
  비운 채 배지를 달고, 하나라도 누르면 화면의 집합 전체가 그 러너의 허용 집합이
  된다(ADR 0052의 의미 그대로). `↩ 갈림으로 되돌리기`가 관측으로 돌린다.
- `선제 전환`의 숫자 상자는 그 행의 select 상태를 따른다. select가
  `갈림 — 유지`면 숫자 상자는 비활성이고 그 러너의 `preempt_pct`는 전송되지
  않는다.

두 러너 가운데 하나라도 계정 카탈로그를 읽지 못하면 계획이 비고 `[적용]`이
잠기는 UI-628r의 규칙은 유지한다. 허용 집합을 그릴 수 없으면 무엇을 쓰는지
화면이 말하지 못하기 때문이다.

### 6.1 계정 선택지의 사용량

`fetchAccountProvider`의 필터를 넓혀 `windows`를 보존하고, `accountRowLabel`이
라벨 뒤에 창 전부를 붙인다: `work@example.com (5h 62% · 7d 41%)`. 상단 사용량
미터와 같은 사용률 표기이고 같은 endpoint를 읽는다. `windows`가 없거나 `pct`가
숫자가 아니면 퍼센트만 빠지고 계정 줄은 그대로 남는다(fail-quiet).

`accountRowLabel`은 설정 창 두 곳(단일·일괄)만 쓰므로 이슈 상세 패널의 계정
줄은 바뀌지 않는다.

## 7. 레포 카드 설정의 통일

레포 카드 `⚙`는 설정 다이얼로그를 `{ scope: 'repo', root_dir }`로 연다. 레일은
`워커`·`세션`·`계정` 세 탭이고, 본문은 `root_dir`에 바인딩한
`createExecutionPane` 하나다 — 지금 인라인 패널이 세그먼트로 전환하던 바로 그 세
섹션이다. 제목은 `<레포 이름> 실행 설정`. `표시` 탭은 워크스페이스 전역 정책이라
연결 저장소 창에만 남는다.

덱에서 다음이 사라진다: `mon2-deck__panel` 껍데기와 그 머리·세그먼트·닫기,
`panelRoot()` 시드, `refreshOpenPanel`, 카드 `⚙`의 `aria-expanded`(대신
`aria-haspopup="dialog"`).

`⚙`를 다시 누르면 창이 닫힌다. 열려 있는 동안 그 저장소 행이 목록에서 사라지면
창을 닫는다.

**계약 변화** — 지금은 헤더 `⚙`(일괄)와 레포 카드 `⚙`(인라인)가 동시에 열릴 수
있어서 UI-628r이 "일괄 실행이 그 저장소에 썼으면 열린 패널이 설정을 다시 읽는다"를
두었다. 창이 하나가 되면 둘은 동시에 열리지 않으므로 이 재읽기 경로는 제거하고,
일괄 적용 뒤 레포 창을 열면 새 값을 읽는 것으로 대체한다.

이 창은 카드가 아니므로 ADR 0014의 슬롯 표 대상이 아니다.

## 8. 서버 투영

`server/ws/monitor-handlers.js`의 워크스페이스 행에 두 필드를 더한다.

- `workspace_accounts` — `get-workspace-accounts`가 내는 것과 같은
  `{ state, values, warnings }`. `session_defaults`와 같은 prewarm 캐시 경로를
  따른다(차가운 캐시는 빈 레이어를 싣고 채워지면 다시 푸시한다).
- `applied_exec_preset` — 큐가 이미 들고 있는
  `{ id, name, revision, applied_at }` 또는 `null`. `provider_limit_policy`처럼
  큐에서 그대로 옮긴다.

새 op도, 기존 op의 payload 변경도 없다. 저장소마다 `get-workspace-accounts`를
왕복하는 대안은 기각한다: `적용 대상`이 바뀔 때마다 N회 왕복이 되고 응답 순서
경쟁을 화면이 떠안는다. `provider_limit_policy`가 같은 이유로 이미 투영에 실려
있다.

구버전 서버가 `workspace_accounts`를 주지 않으면 실행 계정 두 행만 배지 없이
`기본값 사용`에서 시작한다(지금 동작). `applied_exec_preset`이 없으면
`적용된 프리셋` 줄 자체를 그리지 않는다. 대체 문구를 만들지 않는다.

## 9. 오류와 경계

- 모니터 행이 아직 오지 않았으면 두 탭 모두 `저장소 목록을 불러오는 중입니다`를
  유지한다.
- `session_defaults_warnings`가 있는 저장소는 그 경고를 관측에서 제외하지 않고
  값 그대로 읽는다 — 화면이 저장된 사실을 말하는 것이 이 설계의 목적이다.
- 적용 중에는 모든 컨트롤이 비활성이고 관측 재계산도 멈춘다. 실행이 끝나면
  갱신된 스냅샷으로 `편집됨`이 아닌 행이 다시 선다.
- 프리셋 저장·삭제가 `expected_revision`으로 거절되면 기존 문구를 그대로 쓰고
  폼 값은 건드리지 않는다.

   투영.
2. `bulk-tabs` — 일괄 창의 세 탭·관측 결선·프리셋 관리·계정 사용량 라벨.

## 결정 (ADR 후보)

- 전제: ADR UI-wecw — 저장소 defaults와 공통 Worker 주소 적용값을 분리한다. 일괄
  세션 탭은 저장소 defaults(`bdui_url`)만 읽고 쓰며 공통 주소를 건드리지 않는다.
- 전제: ADR 0012 — beads-ui는 dotfiles 계약의 소비자다. `impl_dispatch`에
  워크스페이스 전역 저장이 없다는 계약을 그대로 따라 이 키는 프리셋에만 담고
  저장소에는 쓰지 않는다.
- 전제: ADR 0052 — 한도 자동 전환은 러너별 허용 계정 집합 안에서만 일어난다.
  일괄 폼의 허용 집합은 그 집합 전체를 바꾼다.
- 전제: ADR UI-00lf — 프리셋은 오케스트레이션 3키를 포함한 25키 sparse
  프로필이다. 이 창의 프리셋 관리는 그 어휘를 그대로 쓰고 새 키를 만들지 않는다.
- 모니터 탭의 설정은 저장소의 현재 값을 드러낸다. 여러 저장소 일괄 창은 선택한
  저장소의 값을 읽어 세우는 관측면이자 편집면이고, 값이 갈린 행은 값을 세우지
  않고 `갈림`으로만 서며 사용자가 손대기 전까지 적용에서 빠진다. 일괄 창은 세
  탭(`워커`·`세션`·`계정`)을 두고 프리셋 관리도 갖는다. 레포 카드 `⚙`는 헤더
  `⚙`와 같은 다이얼로그를 그 저장소 단일 모드로 열고 덱 안 인라인 패널은
  없어지며, 두 창이 동시에 열리지 않으므로 일괄 적용 후 열린 패널 재읽기 계약도
  함께 사라진다. 네 조항은 한 화면의 한 재설계라 하나의 결정으로 묶는다. 세 조건
  판단은 다음과 같다. 되돌림 비용이 있다(관측 모듈·편집 상태 기계·세션 탭 적용
  경로·서버의 두 투영 필드·프리셋 관리의 두 번째 호출 지점·덱 패널 제거와
  다이얼로그의 저장소 바인딩 모드가 모두 이 결정에 묶인다). 배경 없이 보면
  의외다(같은 창이 어제까지 현재 값을 일부러 보여주지 않았고, 화면의 값 전부를
  쓴다면서 갈림 행만 빠지며, 같은 pane을 쓰던 두 진입점이 서로 다른 형태로 열려
  있었다). 실재 대안이 있다(갈린 행을 대표값으로 채우기, 읽기 전용 요약만
  덧붙이기, 인라인 패널을 모달 오버레이로만 감싸기, UI-628r 유지).
  `summary`: "모니터 탭의 설정은 저장소의 현재 값을 읽어 세우고 갈린 행은 손대기
  전까지 적용에서 빠지며, 일괄 창이 세 탭과 프리셋 관리를 갖고 레포 카드 설정은
  헤더와 같은 다이얼로그로 열린다" → ADR, supersede UI-628r

## 경계·후속

다른 저장소에서 할 필수 작업과 형제 Bead는 없다. 서버 op와 `app/protocol.md`,
프리셋의 키 집합과 적용 의미, 저장소별 순차 호출과 결과·재적용 형식, 모드 진입
규칙, `적용 대상`의 기본 선택, 계정 카탈로그 실패 시 `[적용]` 잠금은 바꾸지
않는다. 시스템 프롬프트, 자동화·동시 실행 수·직렬 레인의 일괄 적용, 이슈 상세
패널의 계정 줄은 범위 밖이다.

- 관찰: `impl_dispatch`에 워크스페이스 전역 저장을 만드는 안 — dotfiles 계약을
  바꾸는 별개 작업이고 ADR 0012의 소비자 위치를 벗어난다.
- 관찰: 이슈 상세 패널의 계정 줄에도 사용량을 붙이는 안 — 같은 재료로 가능하지만
  사용자가 지목한 표면이 아니고 그 패널의 줄 문법을 건드린다.
- 관찰: `적용 대상`의 전체 선택 토글(`UI-ary8`, quick_fix) — `targetsTemplate`
  한 함수에서 경로만 겹치고 이 설계의 전제가 아니다. 어느 쪽이 먼저 착지하든
  나중 쪽이 흡수한다.
