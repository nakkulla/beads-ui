# Worker 탭 모바일 재배분 + 시각 정돈 (관제 우선 레이아웃)

- Bead: UI-58y2 (route: spec_backed)
- 날짜: 2026-07-28
- 목업: `~/tmp/mockups/2026-07-28-worker-tab-redesign.html` (데스크톱 정돈안 + 모바일 C안 채택, A안의 아코디언 메커니즘 차용)

## 문제

1. 모바일(≤640px)에서 `.worker-lanes`가 세로 스택으로 바뀌지만 5개 페인이
   뷰포트 높이를 `flex: 1`로 강제 분할한다. 후보 페인은 `flex: 0.9`라 화면의
   1/5 미만 — 카드 한 장이 겨우 보이는 수준으로 작다.
2. 데스크톱 Worker 탭은 5개 레인이 동일한 시각적 무게라 "지금 무엇이 실행
   중이고 무엇이 내 결정을 기다리는지"가 한눈에 들어오지 않는다.

## 결정 요약

- 범위: **Worker 탭만**. Board 탭·상세 패널·앱 셸은 건드리지 않는다.
- 모바일 사용 패턴: 모니터링 + 버튼식 큐 적재(질문 C안). 드래그(후보→대기
  적재, 레인 내 reorder)는 데스크톱·터치 모두 현행 유지하고 버튼은 보완재다.
- 모바일 레이아웃: **관제 우선(C안)** — "지금"(실행 중 + PR 대기)을 상단에
  고정하고 나머지 화면을 후보 보드에 준다. 대기·완료는 접힌 스트립으로 두되,
  스트립은 별도 컴포넌트가 아니라 **접힌 상태의 레인**(아코디언)으로 구현한다.
- 시각 시그니처: 레인 상단 2px 스파인·헤더 점·카운트 필이 스테퍼와 같은 생애
  5단계 색(후보 teal → 대기 blue → 실행 violet → PR pink → 완료 green)을
  따른다. 기존 `--stage-*` 토큰 재사용, `tokens.css` 무변경.
- 구현 단계에서 `frontend-design` 스킬 가이드를 적용한다(간격 리듬·포커스
  표시·마감 품질).

## 데스크톱 (>640px)

구조는 현행 5-페인 가로 배치 유지, 시각만 정돈:

- **툴바 재구성**: 좌측 조작(▶ 자동 진행 토글 · 슬롯 스테퍼 · ⚙ 전역 실행
  설정) / 우측 KPI 칩(실행 N · PR 대기 N · 오늘 완료 N · 오늘 토큰 합계).
  KPI 값은 전부 기존 큐 스냅샷·usage 데이터에서 파생 — 새 데이터 소스 없음.
- **레인 스파인**: 페인 상단 2px 보더 + 헤더 점 + 카운트 필을 레인별 생애
  단계 색으로. 후보 페인은 점선 보더·`--bg-candidate` 배경 유지(SOURCE 구분
  불변).
- **실행 타일**: 기존 attempt 데이터만 표시한다 — 경과 시간(`started_at`
  파생), runner/model, 토큰 usage. 큐 스냅샷에 페이즈명·진행률이 없으므로
  진행 바는 만들지 않고, 타일 하단의 비의미적 violet stage 액센트 라인으로
  살아있음만 표현한다(목업의 "구현 · 12분"·퍼센트 바는 데이터 부재로 미채택).
  실행 중 레인 헤더 점은 breathing 애니메이션(`prefers-reduced-motion`이면
  정지).
- **실패·정리 배너**: 좌측 3px 레드 레일 스타일로 정돈, 위치·동작 불변.

## 모바일 (≤640px)

뷰포트 5등분을 폐기하고 페이지 자연 세로 스크롤로 전환:

1. **sticky 리본**: 자동 진행 토글 + 실행/PR/완료 카운트. 스크롤을 내려도
   상태가 항상 한 줄로 읽힌다.
2. **"지금" 패널**: 실행 중 타일(컴팩트) + PR 대기 행을 한 패널로 묶어 리본
   아래 표시. 실행 0건·PR 대기 0건이면 패널 자체를 렌더하지 않는다. 기존
   rtile/mini 템플릿 재조합이며 별도 상태를 만들지 않는다.
3. **대기 스트립**: 한 줄 요약(카운트 + 첫 항목 미리보기). 탭하면 아코디언으로
   펼쳐져 mini 행 표시 + 드래그 reorder 가능. 접힌 상태에서도 `data-lane`을
   유지해 후보→대기 드롭 타깃으로 동작한다.
4. **후보 보드**: 화면의 주인. 내용만큼 높이를 갖고(내부 스크롤 강제 없음)
   페이지와 함께 스크롤 — 크기 문제의 직접 해결.
5. **완료 스트립**: 한 줄 요약(오늘 N건 · 토큰 합계). 탭하면 펼침.

레인 순서는 지금 → 대기 → 후보 → 완료. 접힘 상태는 localStorage에 저장
(`beads-ui.worker.*` 기존 키 패턴), 새로고침 후 복원.

## [대기로 ↴] 버튼

- 후보 카드에 추가하는 큐 적재 버튼. coarse pointer 또는 ≤640px에서만 표시.
- 탭하면 기존 `worker-queue-place` 뮤테이션을 큐 말미 배치로 발행 — 드래그와
  같은 경로·같은 CAS 규율(충돌 시 스냅샷 채택 후 1회 재시도).
- 자격 조건은 드래그와 완전 동일(`hasSpec`만): `⛔ spec 없음` 후보만 비활성.
  `🔒 blocked-with-spec` 후보는 드래그와 마찬가지로 적재 가능(활성) — 현행
  드래그의 의도적 허용을 그대로 따른다.

## 구현 범위

- `app/views/worker/lanes.js`: `paneTemplate` 스파인 클래스 + 접힘(스트립)

- `app/views/worker/index.js`: 모바일 조합("지금" 패널·스트립 순서), [대기로]

- `app/views/worker/running-grid.js`: 실행 타일 시각 정돈(stage 액센트,
  메타 배치) + 관련 테스트.
- `app/styles.css`: worker 섹션 정돈(툴바·스파인·타일·배너·모바일 640px
  블록 재작성). `app/styles/tokens.css`: 무변경.
- 서버·스토어·프로토콜: 무변경. 새 뮤테이션 없음.

## 엣지 케이스

- 빈 레인 문구 유지. 실행 0/PR 0이면 "지금" 숨김.
- 라이트 테마: stage dim/on 토큰의 기존 라이트 오버라이드로 자동 대응.
- `prefers-reduced-motion`: breathing 점·전환 애니메이션 정지.
- 640px 경계 전환 시 접힘 상태는 모바일 전용이므로 데스크톱 렌더에 영향 없음.
