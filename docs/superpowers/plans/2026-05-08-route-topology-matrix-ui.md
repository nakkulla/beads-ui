# Route Topology Matrix and Review Profile UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace legacy `route`/`topology` UI semantics with concrete workflow
settings fields and add editable `review_profile` support.

**Architecture:** Keep the contract snapshot app-owned in
`app/utils/workflow-fields.js`; both Detail and Board consume derived values
from that utility. The server validates the same concrete tuple matrix before
writing Beads metadata, while config/state normalize legacy `route`/`topology`
settings into the new `workflow_settings` section. Tests drive each surface
before implementation, then `npm run build` updates the generated frontend
bundle.

**Tech Stack:** ECMAScript modules, lit-html, WebSocket protocol helpers, Beads
CLI mutation calls, Vitest, TypeScript check via JSDoc.

---
