# 실행 기본값의 실제 모델·effort와 출처 표시 실행 계획 (UI-vvuy)

## Context

- 승인 명세:
  `docs/superpowers/specs/2026-08-18-execution-default-values-design.md`
  @ `a2c2c7879c4bc19a7096981b6a813429f6c40a79`
  (`spec_review=self@a2c2c7879c4bc19a7096981b6a813429f6c40a79`).
- 목표: Worker 설정과 이슈 상세의 bare `(기본)`을 실제 유효
  모델·effort·speed와 `핀/전역/기본` 출처로 바꾸고, 이슈 상세의 유효 실행
  설정을 기본 collapsed인 native `<details>/<summary>` disclosure로 전환한다.
  모델은 compact actual ID를 본문에, full ID를 tooltip·접근성 텍스트에 남긴다.
  동적 effort는 `auto (실행 시 결정)` 또는 `CLI 기본 (미지정)`으로 표시하며
  추측하지 않는다.
- 승인된 시각 기준은 2026-08-18 Visual Companion 목업 v2다. 현재 환경에
  `frontend-design` 스킬이 없어 시각 검토는 그 목업으로 대체했으며, 기존
  설정 다이얼로그와 상세 패널의 토큰·간격·정보 구조 안에서 구현한다.
- 설정 저장값, selector 우선순위, dispatch tuple, Bead metadata와
  `workflow_session_defaults` 어휘는 바꾸지 않는다. display projection의
  부재·불일치·미지원 schema는 `기본값 확인 불가`로 fail-quiet하고 명시값
  편집과 실행 경로는 유지한다.
- `UI-vvuy`의 구현 runtime은 spec gate에서 `codex`로 고정됐다. Phase 실행
  힌트가 없으므로 승인된 selector가 선택한 delegate가 구현하고, controller가
  전체 diff·상태·검증을 직접 판정한다.

## 선행 유닛: dotfiles `dotfiles-wn55`

이 유닛은 다른 저장소와 독립 PR·merge·deploy lifecycle을 가지므로
`UI-vvuy`의 Phase나 phase child가 아니다. 승인 명세를 공유하는
`spec_backed` Bead이며, `UI-vvuy`의 foreign `blocks` dependency가 완료
순서를 강제한다.

작업 범위:

- `docs/contracts/workflow.yaml`에 기존
  `consumer_surface.projection`을 보존한 채 additive
  `consumer_surface.execution_defaults_projection` 등록을 추가한다.
- `scripts/render.py`가 `docs/contracts/harness.yaml`의 등록된 source path만
  읽어 schema v1
  `generated/contracts/execution-defaults.json`을 결정적으로 생성하게 한다.
- `scripts/check-rendered.py`와
  `src/shared/skills/flow/workflow/scripts/check-workflow-contract.py`가
  registration, source path, schema, exact generated bytes를 검증하게 한다.
- 신규 `tests/execution_defaults_projection_contract_test.py`와 기존
  `tests/rendered_instruction_contract_test.py`,
  `tests/contracts/test_workflow_contract.py`에서 harness 값과 projection의
  exact equality, clean render 생성, stale artifact 거부, 기존
  repo-operation projection 비회귀를 고정한다.
- `python scripts/render.py`로 generated artifact를 갱신하고
  `python scripts/check-rendered.py`, focused pytest, workflow contract checker,
  `scripts/run-tests.sh --tier required`를 통과시킨다.
- implementation review와 non-empty dotfiles PR delivery 후 `pr-finish`로
  merge·deploy한다. merged SHA containment, deploy worktree HEAD·tracked-clean,
  render/checker, 설치된 Claude·Codex workflow/harness runtime verifier,
  `bd show dotfiles-wn55 --json`의 `closed`를 확인한다.

위 readback 중 하나라도 없으면 Phase 1에 진입하지 않는다. 재개 시에는
dotfiles Bead·PR·remote containment·repo-operation terminal state를 다시 읽고 첫
미완료 단계부터 이어간다.

## Phase 1: beads-ui — pinned projection, 공용 유효값 resolver, 설정·이슈 상세 UI

서버·artifact 경계:

- merged `dotfiles-wn55` commit의
  `generated/contracts/execution-defaults.json` exact blob을
  `generated/contracts/execution-defaults.json`에 핀하고, source repo/path/
  commit/blob SHA, SHA-256, byte count를 sibling provenance JSON에 기록한다.
  package 배포 목록의 기존 `generated/contracts` 경계를 그대로 사용한다.
- 신규 `server/worker/execution-defaults.js`는 artifact와 provenance를
  process lifetime 동안 한 번 읽고, byte count·digest·schema를 검증한다.
  정상일 때 session facts와 source identity를 반환하고, 파일 부재·parse 실패·
  provenance 불일치·unknown schema는 예외를 전파하거나 다른 기본값으로
  대체하지 않고 structured `supported: false`로 정규화한다.
- 같은 모듈의 wire projector가 session facts에
  `server/worker/policy.js`의 `ORCHESTRATION_MODEL_FALLBACK`, CLI effort
  미지정, literal speed `default`, resolved runner catalog를 합쳐
  `execution_defaults`를 만든다. Worker fallback을 client에 다시
  하드코딩하지 않는다.
- `server/ws/worker-handlers.js#decorateQueue`가 이 비영속 projection을
  `runner_catalog`와 함께 싣는다. queue 저장 schema와 mutation 경로는
  건드리지 않는다. `app/data/worker-queue-store.js` 타입은 field를 optional로
  선언해 구버전 server payload를 계속 받는다.

클라이언트 공용 해석:

- 신규 `app/utils/execution-defaults.js`에 순수 resolver를 둔다. 입력은
  Bead pin, session/queue global, wire defaults, runner catalog, dependent
  selector 상태이며 출력은
  `{ value, source, display, full_value, resolution }`이다.
- session은 `pin > global > harness`, Worker는
  `pin > queue global > launcher fallback`으로 계산한다. reviewer model에
  따른 preset effort, `self/skip/main`의 `해당 없음`,
  `inherit/auto`의 실행 시 결정, unknown token의 raw value+`비호환`을 같은
  함수에서 처리한다.
- `gpt-` prefix만 compact display에서 제거하고 full ID는 보존한다. unset
  `기본값 사용 — …`과 저장된 literal
  `default (일반 · 전역 고정|핀)`은 서로 다른 상태로 유지한다.
- `app/views/detail-panel/exec-settings.js`의 stale static fallback map은
  제거한다. production에서 쓰는 model/catalog normalization helper는 유지하되,
  기본 label을 만드는 모든 활성 경로는 공용 resolver 하나만 사용한다.

설정 다이얼로그:

- `app/views/settings-dialog/session-model.js`가 resolver 결과를 기존 stored
  token과 분리된 option label/view state로 변환한다. 모델·effort dependent
  option은 draft의 현재 reviewer/runtime/model을 기준으로 즉시 재계산한다.
- `app/views/settings-dialog/index.js`의 unset option을
  `기본값 사용 — <actual display>`로 바꾸고 `기본` source badge를 붙인다.
  compact model ID는 option 본문에, resolver의 `full_value`는 control의
  `title` 또는 `aria-label`에 연결한다. Worker tab은 snapshot의
  orchestration projection을 사용한다.
- projection unavailable이면 기존 session warning과 구분되는 warning banner와
  `기본값 확인 불가`를 표시한다. 명시 pin/global 선택, 저장 payload,
  CAS/readback, literal `default` option은 그대로 동작한다.

이슈 상세:

- `app/views/detail-panel/effective-settings.js`가 base를 `null` placeholder로
  만들던 경로를 공용 resolver 기반 structured row로 바꾸고, summary와
  `핀/전역/기본` count도 같은 rows에서 계산한다.
- `app/views/detail-panel/effective-settings-view.js`의 카드 root를 native
  `<details>`, header를 `<summary>`로 바꾼다. initial state는 closed이며
  사용자 toggle 동안만 open 상태를 유지한다. keyboard activation과 browser의
  `aria-expanded` 의미를 보존한다. 행과 collapsed summary의 compact model
  본문에는 resolver의 `full_value`를 `title` 또는 `aria-label`로 연결한다.
- `app/views/detail-panel/index.js`는 issue id 변경, panel clear, close 후
  reopen에서 open state를 false로 재설정한다. expanded body에서만 세부 행,
  source rail·badge, 편집 controls, 구현 preset을 노출하고 collapsed summary는
  actual default values와 세 source count를 보여준다.
- `app/styles.css`는 승인 목업의 compact summary·badge·chevron과 native
  disclosure 상태를 기존 token으로 표현한다. 별도 디자인 시스템이나 새 icon
  dependency는 추가하지 않는다.
- frontend source 변경 후 `npm run build`로
  `app/main.bundle.js`와 `app/main.bundle.js.map`을 갱신한다.

검증: 선행 유닛의 `closed` readback과 pinned blob/provenance를 먼저 확인한 뒤,
아래 RED→GREEN seam의 focused test, Node engine·`npm ls --depth=0` readiness,
`npm run tsc`, `npm test`, `npm run lint`,
`npm run prettier:write`, `npm run build`, bundle tracked diff 확인을 모두
통과시킨다. controller가 `origin/main..HEAD` 전체 diff와 changed-path 범위를
검토하고 implementation review 후 non-empty PR Delivery에서 멈춘다.
